# Godot 核心架构

> 本文档基于 Godot Engine 4.x（源码分支 `4.8 dev`）编写，目标是帮助引擎贡献者与新手快速建立全引擎核心架构的清晰认知。
> 深度为「架构级」：讲清各子系统的职责、关键类、设计意图与调用流程，并以 `file:line` 形式引用源码，不陷入逐行实现。
> 引用约定：以「类名/函数名」为主锚、行号为辅，便于在代码演进后仍可定位。

---

## 一、引擎定位与技术栈

Godot 是一个 **一体化（all-in-one）、跨平台、MIT 许可** 的 2D/3D 游戏引擎，提供编辑器、渲染、物理、音频、脚本语言、动画等完整工具链。

- **实现语言**：核心为 C++（C++17），Tab 缩进、`ColumnLimit: 0`（参见 `.clang-format`、`AGENTS.md`）。
- **构建系统**：仅 **SCons**（`SConstruct` 入口，要求 Python 3.9+、SCons 4.4+，见 `SConstruct:4-5`）。
- **测试框架**：**doctest**（内嵌于 `thirdparty/doctest`），测试位于 `tests/`。
- **脚本**：内置 GDScript；可选 C#（`modules/mono`）、GDExtension（C ABI 原生扩展）。
- **渲染后端**：Vulkan/Forward+/Mobile（`servers/rendering/renderer_rd`）、OpenGL ES 3（`drivers/gl`）、Metal/D3D12 等。
- **目标平台**：`platform/` 下含 windows、linuxbsd、macos、android、ios、web、visionos。

## 二、整体分层架构

Godot 采用清晰的分层架构，底层不依赖上层，上层组合下层能力：

```
┌─────────────────────────────────────────────────────────────────┐
│  工具/脚本层  editor/  modules/(gdscript, mono)  GDExtension     │
├─────────────────────────────────────────────────────────────────┤
│  场景层       scene/  (Node, SceneTree, Viewport, CanvasItem)   │
├───────────────┬───────────────────────────────────┬─────────────┤
│  服务器层      │  servers/                          │             │
│  (前后端分离)  │  rendering/physics/audio/text/     │  平台层      │
│               │  navigation/display/xr/camera      │  platform/  │
├───────────────┴───────────────────────────────────┴─────────────┤
│  核心层       core/                                            │
│               object  variant  class_db  io  os  math  config   │
├─────────────────────────────────────────────────────────────────┤
│  thirdparty/  (内嵌第三方库: vulkan, freetype, jolt, doctest...) │
└─────────────────────────────────────────────────────────────────┘
        ▲ main/ 启动与主循环贯穿各层，驱动整个引擎运转
```

各层职责：

| 层 | 目录 | 职责 |
|----|------|------|
| 核心层 | `core/` | 引擎基石：Object 对象系统、Variant 动态类型、ClassDB 反射、Resource、IO、OS 抽象、数学、内存、线程 |
| 服务器层 | `servers/` | 前后端分离的引擎子系统：渲染、物理、音频、文本、导航、显示、XR、相机 |
| 平台层 | `platform/` | 各目标平台后端：窗口、事件、文件、线程、导出 API |
| 场景层 | `scene/` | 场景图：Node 节点树、SceneTree 主循环、Viewport、2D/3D/动画/GUI 节点 |
| 工具层 | `editor/` | 编辑器运行时（tools 构建）：节点、属性面板、导入导出、项目管理器 |
| 脚本层 | `modules/gdscript`、`modules/mono`、`core/extension` | 脚本语言抽象与具体实现、GDExtension 原生扩展 |
| 模块层 | `modules/` | 可选功能模块（各自 `SCsub` + `config.py`） |
| 第三方 | `thirdparty/` | 内嵌依赖，排除在 lint/格式化之外 |

## 三、核心设计哲学

理解以下五条设计哲学，是读懂 Godot 源码的钥匙：

1. **一切皆 Object**：引擎中几乎所有运行时对象都派生自 `core/object/object.h:355` 的 `Object`。`Object` 提供反射（类名/方法/属性/信号）、`ObjectID` 全局实例表、`notification(int)` 消息分发、信号连接。引用类型通过 `RefCounted`（`core/object/ref_counted.h:36`）实现自动引用计数 + 智能指针 `Ref<T>`。

2. **服务器模式（前后端分离）**：计算密集或需线程化的子系统（渲染/物理/音频…）抽象为「Server」虚接口（位于 `servers/`），默认实现 + 可替换后端。场景层 `scene/` 的节点是这些服务器的「前端」，把服务器 RID 句柄包装成节点树。服务器通过 `*_wrap_mt` 包裹实现线程安全（命令队列模式）。

3. **Variant 统一动态类型**：`core/variant/variant.h:97` 的 `Variant` 是一个可持有全部内置类型（int/string/Vector2/Array/Dictionary/Object/Callable…）的动态类型联合体，是脚本↔C++、序列化、属性系统的统一桥梁。

4. **声明式场景树**：游戏由 `Node` 组成的树来表达，`SceneTree`（`scene/main/scene_tree.h:89`）作为主循环驱动整棵树的处理（`_process`/`_physics_process`）。场景可序列化为 `PackedScene`（`.tscn`），实现数据驱动。

5. **反射驱动工具链**：通过 `GDCLASS`/`GDVIRTUAL` 宏把类注册到 `ClassDB`（`core/object/class_db.h:97`），反射信息同时驱动：脚本绑定、编辑器属性面板、自动文档、序列化、网络 RPC。这是 Godot「编辑器即引擎」能力的基础。

## 五、一帧数据流全景

下图把各章串联，展示一次帧循环中数据如何流经各层（详见各章）：

```
平台事件 (DisplayServer::process_events, 见 07)
   │ 输入事件
   ▼
Main::iteration() (见 01) ── MainTimerSync 步进 ── 物理步循环:
   │   ├─ PhysicsServer3D::sync/flush_queries/step (见 06, 经 *_wrap_mt 命令队列)
   │   ├─ SceneTree::physics_process (见 04) ── Node::_physics_process
   │   │       └─ 脚本覆写经 GDVIRTUAL_CALL (见 08) ── 经 Variant/ClassDB 调用 (见 03)
   │   ├─ NavigationServer::physics_process (见 06)
   │   └─ MessageQueue::flush (见 02) ── 执行 call_deferred
   ├─ 逻辑步: SceneTree::process (见 04) ── Node::_process
   ├─ RenderingServer::sync/draw (见 06) ── RenderingDevice 提交 (Vulkan/RD)
   ├─ GDExtensionManager::frame (见 08) / ScriptLanguage::frame (见 08)
   ├─ AudioServer::update (见 06)
   └─ 渲染结果经 DisplayServer 窗口呈现 (见 07)

贯穿各层的基础:
   对象系统 Object/RefCounted/ObjectDB (见 02)  ── 内存 memnew/memdelete (见 07)
   反射 ClassDB + Variant (见 03)               ── 资源 Resource/RID (见 05)
   构建期 register_*_types 分层注册 (见 10)      ── 平台 detect.py/OS 抽象 (见 07)
```

## 六、统一术语表

| 术语 | 含义 |
|------|------|
| Object | 所有引擎对象的基类，提供反射与消息机制 |
| RefCounted | `Object` 的引用计数派生类，配合 `Ref<T>` 自动管理生命周期 |
| ObjectID | 全局唯一 64 位实例标识，由 `ObjectDB` 分配与查询 |
| Variant | 可持有任意内置类型的动态类型联合体 |
| ClassDB | 全局反射注册表，记录类/方法/属性/信号/常量 |
| Node | 场景图节点，构成树结构 |
| SceneTree | 主循环实现，驱动 Node 树的处理 |
| Resource | `RefCounted` 派生，可序列化、被缓存与共享的资源 |
| Server | 前后端分离的服务器接口（RenderingServer、PhysicsServer…） |
| RID | Resource ID，服务器侧对象的不透明句柄 |
| MainLoop | 主循环抽象接口，`SceneTree` 是其默认实现 |
| GDExtension | 原生扩展的 C ABI，允许外部库注册引擎类型 |
