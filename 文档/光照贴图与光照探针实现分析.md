# 光照贴图与光照探针实现分析

本文档分析 Godot 引擎中光照贴图（LightmapGI）、光照探针（LightmapProbe）和体素全局光照（VoxelGI，原 GIProbe）的实现原理。

---

## 一、系统概览

Godot 提供两套预计算全局光照方案：

| 方案 | 节点 | 数据存储 | 适用场景 |
|------|------|----------|----------|
| 光照贴图 | `LightmapGI` | UV2 空间纹理图集 | 静态场景，高质量间接光照 |
| 体素 GI | `VoxelGI` | 八叉树体素 + 距离场 | 动态物体较多的场景，支持动态间接光 |

`LightmapProbe` 是一个辅助标记节点，用于在光照贴图烘焙时手动指定探针采样位置。

## 三、LightmapGI（光照贴图）

### 3.1 核心类型

#### `LightmapGI`（场景节点）

继承自 `VisualInstance3D`，负责烘焙流程和运行时光照贴图分配。

```
关键成员：
- bake_quality        烘焙质量（Low/Medium/High/Ultra）
- bounces             间接光反弹次数（0~16）
- directional         是否使用球谐函数（SH）存储方向性光照
- shadowmask_mode     阴影遮罩模式（None/Replace/Overlay/Only）
- gen_probes          自动生成探针的细分级别
- light_data          关联的 LightmapGIData 资源
```

#### `LightmapGIData`（资源）

继承自 `Resource`，存储烘焙结果，扩展名 `.lmbake`。

```
关键成员：
- combined_light_texture      合并后的光照贴图纹理（Texture2DArray）
- combined_shadowmask_texture 合并后的阴影遮罩纹理
- uses_spherical_harmonics    是否使用 SH（方向性光照）
- users[]                     网格→UV 映射关系（NodePath, uv_scale, slice_index）
- lightmap (RID)              渲染服务器端资源句柄
- bounds                      探针捕获的 AABB 边界
- baked_exposure              烘焙曝光归一化值
- lightprobe_hash             探针位置哈希（用于判断是否需要重建 BSP）
```

探针捕获数据（存储在渲染服务器端）：
- `points` — 探针世界坐标
- `point_sh` — 每个探针 9 个 SH 系数（`Color` 数组，共 `count × 9`）
- `tetrahedra` — Delaunay 四面体索引（每 4 个一组）
- `bsp_tree` — BSP 加速树（每节点 6 个 int32：plane.xyz + plane.d + over + under）

#### `Lightmapper`（抽象基类）

定义光照贴图烘焙器的接口：

```cpp
virtual void add_mesh(const MeshData &p_mesh) = 0;
virtual void add_directional_light(...) = 0;
virtual void add_omni_light(...) = 0;
virtual void add_spot_light(...) = 0;
virtual void add_area_light(...) = 0;
virtual void add_probe(const Vector3 &p_position) = 0;
virtual BakeError bake(...) = 0;
```

通过静态工厂函数 `create()` 创建具体实现（`LightmapperRD`）。

#### `LightmapperRD`（GPU 烘焙器）

继承 `Lightmapper`，使用 RenderingDevice 在 GPU 上执行烘焙。

关键内部结构：
- `BakeParameters` — 烘焙全局参数（世界尺寸、网格大小、反弹次数等）
- `Light` — 光源参数（位置、方向、颜色、能量、衰减等）
- `Vertex` / `Triangle` — 网格顶点/三角形数据
- `Probe` — 探针位置
- `Seam` — UV 接缝（用于混合）

### 3.2 烘焙核心流程

`LightmapGI::bake()` 是入口函数（`scene/3d/lightmap_gi.cpp:1060`），流程如下：

```
┌─────────────────────────────────────────────────────────┐
│ STEP 1: 收集场景数据                                      │
│   _find_meshes_and_lights() 遍历场景树                    │
│   - 收集 GI_MODE_STATIC 的 MeshInstance3D（需 UV2+法线）  │
│   - 收集 Light3D（bake_mode != DISABLED）                │
│   - 收集 LightmapProbe 位置                              │
│   - 通过 bake_render_uv2() 渲染 albedo/emission 到 UV2   │
├─────────────────────────────────────────────────────────┤
│ STEP 2: 生成探针                                         │
│   - 若 gen_probes == DISABLED：仅在边界 8 个端点放置       │
│   - 否则：构建八叉树（GenProbesOctree），沿几何体表面       │
│     按细分级别自动生成探针位置                              │
│   - _plot_triangle_into_octree() 将三角形插入八叉树        │
│   - _gen_new_positions_from_octree() 生成最终探针位置      │
├─────────────────────────────────────────────────────────┤
│ STEP 3: 提交数据到 Lightmapper                           │
│   - lightmapper->add_mesh() / add_*_light() / add_probe()│
│   - 构建区域光纹理图集（_build_area_light_texture_atlas）  │
├─────────────────────────────────────────────────────────┤
│ STEP 4: 执行 GPU 烘焙                                    │
│   lightmapper->bake() → LightmapperRD::bake()           │
│   内部流程见 3.3                                         │
├─────────────────────────────────────────────────────────┤
│ STEP 5: 保存纹理                                         │
│   _save_and_reimport_atlas_textures()                    │
│   - 光照贴图保存为 EXR（HDR）                            │
│   - 阴影遮罩保存为 PNG                                   │
│   - 生成 .import 配置，重新导入为 Texture2DArray          │
├─────────────────────────────────────────────────────────┤
│ STEP 6: 构建探针加速结构                                  │
│   - Delaunay3D::tetrahedralize() 四面体化                │
│   - _compute_bsp_tree() 构建 BSP 树                      │
│   - set_capture_data() 提交到渲染服务器                   │
├─────────────────────────────────────────────────────────┤
│ STEP 7: 保存 LightmapGIData 资源                         │
│   ResourceSaver::save(gi_data)                           │
└─────────────────────────────────────────────────────────┘
```

### 3.3 GPU 烘焙管线（LightmapperRD::bake）

`modules/lightmapper_rd/lightmapper_rd.cpp:1104`

```
1. _blit_meshes_into_atlas()
   - 将所有网格的 albedo/emission 按 UV2 布局打包到图集
   - 计算图集尺寸和切片数

2. 创建 GPU 纹理
   - albedo_array_tex (RGBA8)
   - emission_array_tex (RGBA16F)
   - position_tex / unocclude_tex / normal_tex (RGBA32F)
   - light_accum_tex / light_dest_tex (RGBA16F, 若 SH 则 4x 层)
   - shadowmask_tex (RGBA8, 可选)

3. _create_acceleration_structures()
   - 构建三角形网格 BVH/Cluster 加速结构
   - 构建空间网格（grid_texture）用于光线追踪
   - 上传探针位置 buffer

4. _raster_geometry()
   - 光栅化几何体到 position/normal/unocclude 纹理
   - 使用 lm_raster.glsl 着色器

5. 直接光照计算（lm_compute.glsl）
   - 对每个纹素发射光线，计算直接光照
   - 支持方向光/点光/聚光/区域光

6. 间接光照反弹（循环 bounces 次）
   - 每次反弹：从当前光照结果发射光线
   - 累积到 light_accum_tex
   - 交换 source/dest 纹理

7. _dilate()
   - 扩展光照到 UV 接缝外的空白区域

8. _denoise()（可选）
   - 内置降噪器或外部 OIDN

9. _pack_l1()（若 directional）
   - 将 4 层 SH 数据打包为方向性光照贴图

10. 探针 SH 计算
    - 对每个探针位置发射光线
    - 计算 9 个球谐系数
```

### 3.4 运行时渲染

烘焙完成后，`LightmapGI` 通过 `_assign_lightmaps()` 将光照贴图绑定到各网格实例：

```cpp
RS::get_singleton()->instance_geometry_set_lightmap(
    instance_id,        // 网格实例 RID
    get_instance(),     // LightmapGI 实例 RID
    uv_scale,           // 该网格在图集中的 UV 偏移/缩放
    slice_index         // 纹理切片索引
);
```

渲染服务器端 `Lightmap` 结构（`light_storage.h:351`）：

```cpp
struct Lightmap {
    RID light_texture;              // 光照贴图纹理
    RID shadow_texture;             // 阴影遮罩纹理
    bool uses_spherical_harmonics;  // 是否 SH
    AABB bounds;                    // 探针边界
    PackedVector3Array points;      // 探针位置
    PackedColorArray point_sh;      // 探针 SH 系数
    PackedInt32Array tetrahedra;    // 四面体索引
    PackedInt32Array bsp_tree;      // BSP 加速树
};
```

渲染时，动态物体通过 BSP 树定位所在四面体，插值 4 个顶点的 SH 系数获得间接光照。

### 3.5 探针插值加速结构

#### BSP 树构建

`_compute_bsp_tree()`（`lightmap_gi.cpp:527`）：

1. 对 Delaunay 四面体的所有面进行评分
2. 选择最佳分割平面（平衡性 × 分离度）
3. 递归构建二叉树
4. 叶节点存储四面体索引（负数编码：`-(index + 1)`）

运行时查询：从根节点开始，根据点与平面的关系遍历到叶节点，找到包含该点的四面体。

#### 八叉树探针生成

`GenProbesOctree` 结构用于自动探针布局：

1. 将场景 AABB 按细分级别划分为均匀网格
2. `_plot_triangle_into_octree()` 将三角形标记到覆盖的网格单元
3. `_gen_new_positions_from_octree()` 在有几何体的单元顶点处生成探针
4. 避免与用户手动放置的 `LightmapProbe` 过近（距离 < 0.5 单元格）

## 四、LightmapProbe（光照探针标记）

### 4.1 实现

`LightmapProbe` 是一个极简的标记节点（`scene/3d/lightmap_probe.h`）：

```cpp
class LightmapProbe : public Node3D {
    GDCLASS(LightmapProbe, Node3D)
public:
    LightmapProbe();
};
```

它本身不包含任何数据或逻辑，仅作为场景中的位置标记。

### 4.2 工作原理

在 `LightmapGI::_find_meshes_and_lights()` 中（`lightmap_gi.cpp:480`）：

```cpp
LightmapProbe *probe = Object::cast_to<LightmapProbe>(p_at_node);
if (probe) {
    Transform3D xf = get_global_transform().affine_inverse() * probe->get_global_transform();
    probes.push_back(xf.origin);
}
```

收集到的探针位置会：
1. 扩展烘焙边界（`bounds.expand_to(probes_found[i])`）
2. 传递给 `lightmapper->add_probe()` 参与 SH 计算
3. 在自动生成探针时，避免与手动探针位置重叠

## 五、VoxelGI（体素全局光照，原 GIProbe）

### 5.1 核心类型

#### `VoxelGI`（场景节点）

继承自 `VisualInstance3D`，定义 GI 影响区域和烘焙参数。

```
关键成员：
- subdiv          细分级别（64/128/256/512）
- size            影响区域尺寸（Vector3）
- probe_data      关联的 VoxelGIData 资源
- camera_attributes  相机曝光属性
```

#### `VoxelGIData`（资源）

继承自 `Resource`，存储体素化结果。

```
关键成员：
- probe (RID)         渲染服务器端资源句柄
- to_cell_xform       世界空间→体素空间的变换
- bounds              AABB 边界
- octree_size         八叉树尺寸
- dynamic_range       动态范围（1~8）
- energy              能量乘数
- propagation         传播系数（0~1）
- bias / normal_bias  偏移参数
- interior            是否室内场景
- use_two_bounces     是否使用二次反弹
```

数据通过 `allocate()` 提交到渲染服务器：
- `octree_cells` — 八叉树结构数据（字节数组）
- `data_cells` — 体素光照数据（albedo + emission + normal）
- `distance_field` — 3D 距离场（用于 SDF 追踪）
- `level_counts` — 每层级的单元数量

#### `Voxelizer`（体素化器）

`scene/3d/voxelizer.h` — 将网格体素化为八叉树。

```
关键结构：
- Cell            体素单元（children[8], albedo, emission, normal, alpha, x/y/z, level）
- CellSort        排序用键（Morton 编码）
- MaterialCache   材质纹理缓存（128×128 albedo/emission）

关键方法：
- begin_bake()    初始化八叉树
- plot_mesh()     将网格绘制到体素
- end_bake()      完成体素化，生成 mipmap
- get_sdf_3d_image()  生成距离场
```

`VoxelGI::bake()`（`scene/3d/voxel_gi.cpp:434`）：

### 5.3 运行时渲染

渲染服务器端 `VoxelGI` 结构（`renderer_rd/environment/gi.h:68`）：

```cpp
struct VoxelGI {
    RID octree_buffer;      // 八叉树结构 GPU buffer
    RID data_buffer;        // 体素数据 GPU buffer
    RID sdf_texture;        // 距离场 3D 纹理
    Vector<int> level_counts; // 每层单元数
    Transform3D to_cell_xform;
    AABB bounds;
    Vector3i octree_size;
    float dynamic_range, energy, propagation, bias, normal_bias;
    bool interior, use_two_bounces;
};
```

运行时渲染流程（`voxel_gi.glsl`）：

1. **直接光照注入**：将静态光源的光照写入体素（`sdfgi_direct_light.glsl`）
2. **传播**：从高层级向低层级传播间接光照（`propagation` 参数控制）
3. **锥追踪**：从着色点沿法线半球发射多条光线，在八叉树中追踪
4. **二次反弹**（可选）：追踪结果再次作为光源进行第二次传播
5. **结果**：输出间接漫反射光照（ambient）和间接镜面反射（reflection）

渲染标志位（`render_forward_clustered.h:282`）：
```cpp
INSTANCE_DATA_FLAG_USE_VOXEL_GI = 1 << 10  // 标记实例使用 VoxelGI
```

### 5.4 八叉树数据结构

Voxelizer 的 `Cell` 结构：

```cpp
struct Cell {
    uint32_t children[8];   // 子节点索引（CHILD_EMPTY = 0xFFFFFFFF）
    float albedo[3];        // 反照率
    float emission[3];      // 自发光/累积光照
    float normal[3];        // 法线
    float alpha;            // 上采样用
    uint16_t x, y, z;      // 体素坐标
    uint16_t level;         // 层级（0 = 最粗）
};
```

GPU 端数据编码为紧凑字节数组：
- `octree_cells` — 八叉树节点（每节点 32 字节：8 个子节点索引）
- `data_cells` — 叶节点数据（albedo + emission + normal，压缩格式）
- `level_counts` — 每层节点数，用于构建 mipmap 层级

## 六、两套方案对比

| 维度 | LightmapGI | VoxelGI |
|------|-----------|---------|
| 光照质量 | 高（逐纹素） | 中（受体素分辨率限制） |
| 动态物体 | 仅通过探针插值获得间接光 | 完全支持动态间接光 |
| 烘焙时间 | 较长（GPU 光线追踪） | 较短（CPU 体素化） |
| 内存占用 | 纹理图集（与 UV2 分辨率相关） | 八叉体素（与 subdiv 相关） |
| 渲染开销 | 低（纹理采样） | 中（锥追踪） |
| 支持渲染器 | Forward+/Mobile/Compatibility | 仅 Forward+ |
| 方向性光照 | 可选 SH（directional 模式） | 内置（体素法线） |
| 阴影遮罩 | 支持（Shadowmask） | 不支持 |
