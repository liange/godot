# 05 资源系统

## 职责定位

资源系统管理引擎中所有可序列化、可共享、可引用的数据对象--纹理、网格、材质、音频流、字体、场景（`PackedScene`）、脚本等。`Resource` 经引用计数自动管理生命周期，通过 `ResourceLoader`/`ResourceSaver` 配合可插拔的「资源格式」实现多格式加载与保存，`ResourceUID` 提供跨重命名的稳定引用，`ResourceCache` 全局去重缓存，PCK 打包支持发布分发。资源系统是「数据驱动」的载体，位于 `core/io/`，与对象系统、类型系统、场景树紧密协作。

## Resource 基类

`Resource`（`core/io/resource.h:52 : public RefCounted`）派生自 `RefCounted`（见 [02 对象系统](02-对象系统.md)），设 `AncestralClass::RESOURCE`。

### 核心成员（`resource.h:69-100`）

```cpp
String name;
String path_cache;          // 资源路径（在缓存中的键）
String scene_unique_id;     // 场景内唯一 ID
#ifdef TOOLS_ENABLED
uint64_t last_modified_time;
uint64_t import_last_modified_time;
String import_path;
#endif
bool local_to_scene = false;
Node *local_scene = nullptr;
SelfList<Resource> remapped_list;   // 翻译重映射链
```

### 路径与缓存

- `set_path`/`get_path`（`resource.h:144-145`）：设置/获取路径，会更新 `ResourceCache`（移除旧键、插入新键）。
- `_take_over_path`（`resource.h:114`）：当资源无路径时占用一个空闲路径（用于内置资源）。
- `is_built_in()`（`resource.h:147`）：判断是否为内置资源（路径为空、含 `::` 或 `local://` 前缀，如场景内子资源）。
- `get_base_extension()`/`RES_BASE_EXTENSION(ext)`（`resource.h:59/41`）：资源类的「基础扩展名」（如 `tres`/`tscn`/`res`），`register_custom_data_to_otdb` 注册到 ClassDB 的 `resource_base_extensions`（见 [03](03-类型系统与反射.md)）。

### 信号与变更通知

- `emit_changed`（`resource.h:137`）：发射 `changed` 信号，通知依赖此资源的对象（如纹理变化触发材质重绘）。
- `connect_changed`/`disconnect_changed`（`resource.h:138-139`）：便捷连接，默认 `CONNECT_REFERENCE_COUNTED`。
- `_block_emit_changed`/`_unblock_emit_changed`（`resource.h:110-111`）：批量修改时暂时阻塞 `changed`，避免中间态触发重绘。`EmitChangedState`（`resource.h:82-87`）三态管理。

### 复制与本地化

- `duplicate(bool deep)`/`duplicate_deep`（`resource.h:154-155`）：浅/深复制，`DuplicateParams`（`resource.h:63-67`）控制深复制模式与 `local_scene` 重映射。`thread_duplicate_remap_cache`（`resource.h:95`）线程局部缓存避免深复制时重复。
- `local_to_scene`（`resource.h:161-163`）：标记资源「每个场景实例独立」。场景实例化时调用 `setup_local_to_scene`/`_setup_local_to_scene`（`resource.h:117/163`）复制一份给该实例，避免共享可变状态。
- `reset_state()`（`resource.h:133`）：清理由 `_get_property_list`/`_validate_property` 产生的非暴露状态，供编辑器重载时调用。

### RID 桥接

`get_rid()`（`resource.h:184`）/ `_get_rid`（`resource.h:119`）：部分资源（如 `Texture2D`、`Mesh`）封装服务器对象，返回其 RID（见 [06 服务器架构](06-服务器架构.md)）。资源析构时释放对应 RID。

## ResourceCache 全局缓存

`ResourceCache`（`core/io/resource.h:197`）是路径->资源的全局单例缓存，实现去重：

```cpp
class ResourceCache {
    static Mutex lock;
    static HashMap<String, Resource *> resources;
#ifdef TOOLS_ENABLED
    static HashMap<String, HashMap<String, String>> resource_path_cache;  // tscn -> {path: id}
    static RWLock path_cache_lock;
#endif
public:
    static bool has(const String &p_path);
    static Ref<Resource> get_ref(const String &p_path);
    static void get_cached_resources(List<Ref<Resource>> *p_resources);
    static int get_cached_resource_count();
};
```

- 加载时若 `CacheMode` 为 `REUSE`（默认），先查缓存命中则直接返回已有 `Ref`，避免重复加载同一文件。
- `Resource` 构造/析构时经 `friend` 关系维护缓存。`set_path` 触发缓存键迁移。
- `resource_path_cache`（TOOLS）记录场景文件内资源的路径-ID 映射，配合 `Resource::set_resource_id_for_path`（`resource.h:187`）保持跨保存的 ID 稳定。

## ResourceLoader 加载

`ResourceLoader`（`core/io/resource_loader.h:103`）是加载入口，全部静态，采用「格式链 + 缓存 + 线程加载」设计。

### ResourceFormatLoader 格式

`ResourceFormatLoader`（`resource_loader.h:48 : public RefCounted`）是可插拔格式基类：

```cpp
virtual Ref<Resource> load(path, original_path, r_error, use_sub_threads, r_progress, cache_mode);
virtual void get_recognized_extensions(List<String> *) const;
virtual bool recognize_path(const String &p_path, const String &p_type_hint) const;
virtual void get_dependencies(path, List<String> *deps, add_types);
virtual String get_resource_type(const String &p_path) const;
```

- `ResourceLoader::loader[]`（`resource_loader.h:156`，最多 64 个）按注册顺序保存格式。
- `add_resource_format_loader`（`resource_loader.h:263`）：注册格式，`at_front` 可插队（导入器优先）。
- 内置格式：`ResourceFormatLoaderBinary`（`.res`/`.scn`）、`ResourceFormatImporter`（导入资源，见下文）、`ResourceFormatLoaderImage`、翻译 PO 等，在 `register_core_types()` 注册（见 [03](03-类型系统与反射.md) 与 `register_core_types.cpp:166-180`）。
- GDExtension/模块可追加自定义格式。

### 加载流程

`load(path, type_hint, cache_mode, r_error)`（`resource_loader.h:259`）是同步入口，内部经 `_load_start`/`_load_complete`（`resource_loader.h:147-148`）：

1. 路径规范化与重映射：`_path_remap`（`resource_loader.h:168`）处理翻译重映射（`translation_remaps`，`resource_loader.h:166`，如不同语言的纹理）。
2. 缓存查询：`CacheMode::REUSE` 时查 `ResourceCache`，命中返回。
3. 格式识别：遍历 `loader[]`，找首个 `recognize_path` 命中的格式。
4. 实际加载：`ResourceFormatLoader::load` 解析文件、按 `ClassDB::instantiate` 创建对象、应用属性（`set`，经 `Variant`，见 [03](03-类型系统与反射.md)）。二进制格式由 `resource_format_binary.cpp` 的 `ResourceFormatLoaderBinary` 处理。
5. 递归依赖：资源引用其他资源时递归加载，`get_dependencies` 提供依赖列表。
6. 入缓存：加载成功后注册到 `ResourceCache`，`set_path` 触发。

### 线程加载

`load_threaded_request`/`load_threaded_get_status`/`load_threaded_get`（`resource_loader.h:249-251`）支持后台加载：

- `ThreadLoadTask`（`resource_loader.h:111` 前向声明，`thread_load_tasks`，`resource_loader.h:235`）：记录每个进行中的加载任务。
- `LoadToken`（`resource_loader.h:134 : public RefCounted`）：加载句柄，含 `local_path`、用户引用计数 `user_rc`，支持多请求复用同一任务。
- `LoadThreadMode`（`resource_loader.h:128-132`）：`FROM_CURRENT`（当前线程，可能阻塞）、`SPAWN_SINGLE`（单线程）、`DISTRIBUTE`（分布到工作线程池）。
- `ThreadLoadStatus`（`resource_loader.h:121-126`）：`INVALID_RESOURCE`/`IN_PROGRESS`/`FAILED`/`LOADED`。
- 子资源可并行加载（`use_sub_threads`），配合 `WorkerThreadPool`（见 [02](02-对象系统.md)），`r_progress` 报告进度。
- `BINARY_MUTEX_TAG`（`resource_loader.h:145`）的 `SafeBinaryMutex` 防止同路径并发重复加载。

### CacheMode

`CacheMode`（`resource_loader.h:114-119`，定义在 `resource_loader_constants.h`）：

| 模式 | 行为 |
|------|------|
| `CACHE_MODE_IGNORE` | 不查缓存、不存缓存 |
| `CACHE_MODE_REUSE` | 命中缓存则复用（默认） |
| `CACHE_MODE_REPLACE` | 替换缓存中的旧资源（重载） |
| `CACHE_MODE_IGNORE_DEEP` | 自身不缓存，但子资源正常缓存 |
| `CACHE_MODE_REPLACE_DEEP` | 自身与子资源都替换 |

`CACHE_MODE_REPLACE` 用于编辑器重载文件：保留 `Ref` 指针，原地更新属性，使所有引用者自动看到新内容。

## ResourceSaver 保存

`ResourceSaver` 与 `ResourceLoader` 对称：

- `ResourceFormatSaver`：格式保存基类，`save(ref, path, flags)` 写出资源。
- `ResourceSaver::save(ref, path, flags)`：选格式保存。
- 二进制格式 `ResourceFormatSaverBinary`（`resource_format_binary.cpp`）写 `.res`。
- 文本格式（`.tres`/`.tscn`）由对应模块/scene 提供，经 `Variant` 文本序列化（`variant_parser.cpp`，见 [03](03-类型系统与反射.md)）。
- `ResourceFormatImporterSaver`（`resource_importer.h:171`）：导入资源的保存支持。
- 保存时遍历 `get_property_list`，按 `PROPERTY_USAGE_STORAGE` 筛选属性（见 [03](03-类型系统与反射.md)）。

## ResourceUID 稳定引用

`ResourceUID`（`core/io/resource_uid.h:41 : public Object`）解决「文件重命名/移动后引用失效」问题：

```cpp
typedef int64_t ID;        // resource_uid.h:44
ID create_id();            // 生成新 ID
ID create_id_for_path(const String &p_path);   // 为路径创建 ID
bool has_id(ID p_id) const;
String get_id_path(ID p_id) const;             // ID -> 路径
ID text_to_id(const String &p_text) const;     // "uid://xxxx" -> ID
```

- 路径形式 `uid://xxxxxxxxxxxx`，比 `res://` 路径更稳定。
- ID 持久化在 `.god/uid_cache.bin`，编辑器导入时为每个资源分配 ID。
- 加载时 `ResourceUID::ensure_path` 把 `uid://` 转为 `res://` 路径（见 `main.cpp:4243` 的主场景解析）。
- `ResourceUIDScanForUIDOnStartup`（`resource_uid.h:39`）回调供平台在启动时扫描 UID。
- `PackedScene` 的 `SceneState` 优先用 UID 引用子资源，回退到路径。

## PCK 打包

`PackedData`（`core/io/file_access_pack.h:64`）把多个文件聚合为单一 PCK（或嵌入可执行文件），用于发布。

### 结构

- `PackedData` 单例：维护打包文件路径表，`FileAccess` 打开时优先查 PCK。
- `PackSource`（`file_access_pack.h` 抽象）：打包源基类，`try_open_pack(path, replace, offset, key)`（`file_access_pack.h:163`）加载一个包。
- `PackedSourcePCK`（`file_access_pack.h:168`）：标准 `.pck` 文件源。
- `PackedSourceDirectory`（`file_access_pack.h:174`）：把目录当包（开发用）。
- `PackedSourceZIP`（`file_access_zip.h`）：ZIP 源。
- `add_path`（`file_access_pack.h:134`）：注册一个打包文件条目（包内路径、真实路径/偏移、大小、MD5、是否替换、是否加密/打包/delta）。

### 工作方式

1. 启动时（`OS` 初始化或 `Main::setup`）尝试加载可执行文件末尾嵌入的 PCK（`get_embedded_pck_offset`，见 [07](07-OS与平台抽象.md)），或 `--main-pack` 指定的包。
2. `FileAccess::open` 先查 `PackedData`，命中则返回从包内读取的 `FileAccess`；否则走平台文件系统。
3. 加密 PCK 用 `decryption_key` 解密，`delta` 支持增量包。
4. `PCKPacker`（`pck_packer.h`）可生成 PCK，供导出使用。

这让发布产物可以是单文件（可执行文件+嵌入 PCK），`res://` 路径透明地映射到包内条目。

## 导入系统

许多资源（PNG、OGG、FBX…）不能直接被引擎使用，需「导入」为引擎原生格式。框架在 `core/io/resource_importer.h`，实际导入器在 `editor/import/`（见 [09 编辑器架构](09-编辑器架构.md)）。

### ResourceFormatImporter

`ResourceFormatImporter`（`resource_importer.h:41 : public ResourceFormatLoader`）是特殊格式，它本身不解析文件，而是：

1. 识别导入资源（`.import` 元数据文件标记）。
2. 查找对应的 `ResourceImporter`。
3. 加载已导入的 `.god/imported/` 缓存产物（`.scn`/`.ctex` 等）。

它在 `register_core_types` 中 `add_resource_format_loader` 时插队（`at_front`，`register_core_types.cpp:171-172`），优先于原生格式。

### ResourceImporter

`ResourceImporter`（`resource_importer.h:110 : public RefCounted`）是导入器基类：

```cpp
virtual String get_importer_name() const = 0;       // 如 "texture"
virtual String get_visible_name() const = 0;        // 如 "Texture"
virtual void get_recognized_extensions(List<String> *) const = 0;
virtual Error import(ResourceUID::ID source_id, String source_file, String save_path,
                      HashMap<StringName,Variant> options,
                      List<String> *r_platform_variants, List<String> *r_gen_files, ...) = 0;
```

- 导入发生在编辑器导入管线（`EditorFileSystem` 扫描 -> 选 `ResourceImporter` -> 调 `import` -> 产物存 `.god/imported/`，元数据存 `.import`）。
- 运行时 `ResourceFormatImporter` 直接读产物，无需源文件，因此发布包不含源 PNG/FBX，只含导入产物（除非 `--export-keep-source`）。
- `import_group_file`（`resource_importer.h:162`）支持组导入（如多 sprite 的图集）。
- 平台变体（`r_platform_variants`）：为不同平台生成不同产物（如 S3TC vs ETC 纹理），运行时按平台选。

## 文件与目录抽象

`FileAccess`（`core/io/file_access.h`）与 `DirAccess`（`core/io/dir_access.h`）是平台无关的文件/目录抽象：

- `FileAccess::open(path, flags)` 工厂：按路径前缀（`res://`、`user://`、`userdata://`）与 PCK 查找选后端（见 [07](07-OS与平台抽象.md)）。
- 变体：`FileAccessCompressed`、`FileAccessEncrypted`、`FileAccessMemory`、`FileAccessPack`（包内）、`FileAccessZip`、`FileAccessPatched`。
- `DirAccess` 类似，提供目录列举、创建、删除。
- 路径解析：`res://` -> 项目根（或 PCK），`user://` -> 用户数据目录（`OS::get_user_data_dir`）。

## ASCII：资源加载流水线

```
   ResourceLoader::load("res://icon.png")
        │
        ├─ _path_remap()  (翻译重映射)
        ├─ CacheMode::REUSE? ──► ResourceCache::has() ──命中──► 返回 Ref
        │
        ├─ 遍历 loader[] 找格式
        │     ├─ ResourceFormatImporter (优先) ──► 查 .import ──► 读 .god/imported/icon.ctex
        │     └─ ResourceFormatLoaderBinary ──► 解析 .res/.scn
        │
        ├─ ResourceFormatLoader::load()
        │     ├─ ClassDB::instantiate(type)
        │     ├─ 逐属性 set(value)  (Variant -> PropertyInfo)
        │     └─ 递归加载子资源依赖
        │
        ├─ ResourceCache 注册 (path -> Resource*)
        ├─ Resource::set_path()
        └─ 返回 Ref<Resource>
                              │
            ┌──────────────────┴───────────────────┐
            ▼                                       ▼
   get_rid() -> RenderingServer 句柄          emit_changed -> 依赖者更新
   (纹理/网格等服务器资源)                      (材质/动画等)
```

## 与其他子系统关系

- **对象系统**：`Resource` 经 `RefCounted` + `Ref<T>` 管理生命周期，`emit_changed` 用信号机制，见 [02 对象系统](02-对象系统.md)。
- **类型系统**：`Resource` 经 `GDCLASS` 注册，`RES_BASE_EXTENSION` 登记扩展名，加载靠 `ClassDB::instantiate` + `set`，见 [03 类型系统与反射](03-类型系统与反射.md)。
- **节点/场景树**：`PackedScene` 是 `Resource`，`Resource::local_to_scene` 支持每实例独立，见 [04 节点与场景树](04-节点与场景树.md)。
- **服务器**：服务器资源（纹理、网格、着色器）经 `Resource::get_rid` 桥接，`Resource` 析构释放 RID，见 [06 服务器架构](06-服务器架构.md)。
- **OS/平台**：`FileAccess`/`DirAccess` 平台后端、PCK 嵌入与 `OS::get_user_data_dir`，见 [07 OS 与平台抽象](07-OS与平台抽象.md)。
- **编辑器**：导入管线、`EditorFileSystem` 扫描、资源重载都在编辑器侧驱动，见 [09 编辑器架构](09-编辑器架构.md)。
