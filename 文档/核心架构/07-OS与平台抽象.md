# 07 OS 与平台抽象

## 职责定位

OS 与平台抽象层屏蔽底层操作系统差异，向上提供统一的「环境、时间、内存、线程、文件、输入」接口。`OS` 是平台单例基类，`DisplayServer` 负责窗口与事件，内存/线程原语定义在 `core/os/` 与 `core/templates/`，文件/目录抽象在 `core/io/`。各目标平台在 `platform/` 提供具体后端，由 `detect.py` 在 SCons 构建时探测能力与配置。本章是「引擎如何跨平台」的答案。

## OS 抽象基类

`OS`（`core/os/os.h:46`）是抽象单例基类，`OS::get_singleton()`（`os.h:146`）全局访问。各平台派生（如 `OS_Windows`、`OS_LinuxBSD`、`OS_MacOS`），在平台 `main()` 中栈上构造（见 [01](01-启动与主循环.md) 的 `OS_Windows os(nullptr)`）。

### 生命周期（`os.h:130-139`）

```cpp
virtual void initialize() = 0;          // 平台底层初始化
virtual void initialize_joypads() = 0;
virtual void set_main_loop(MainLoop *) = 0;  // 持有主循环
virtual void delete_main_loop() = 0;
virtual void finalize() = 0;            // 平台清理
virtual void finalize_core() = 0;       // 核心层清理
virtual MainLoop *get_main_loop() const = 0;
```

`Main::setup` 调 `OS::initialize()`（`main.cpp:965`），`Main::cleanup` 调 `finalize`。`OS::run()`（平台实现，如 `os_windows.cpp:2348`）承载帧循环（见 [01](01-启动与主循环.md)）。

### 环境与进程

- `get_executable_path()`（`os.h:214`）、`get_user_data_dir()`（`os.h:327-328`）：可执行路径与用户数据目录（`user://` 解析目标）。
- `get_cmdline_args()`/`get_cmdline_user_args()`/`get_cmdline_platform_args()`（`os.h:242-244`）：命令行参数。
- `create_process`/`create_instance`/`open_with_program`/`is_process_running`/`kill`（`os.h:218-222`）：子进程管理。
- `open_dynamic_library`（`os.h:199`）：动态库加载（GDExtension 用，见 [08](08-脚本与扩展.md)）。
- `get_locale()`（`os.h:310`）、`is_sandboxed()`（`os.h:365`）、`is_userfs_persistent()`（`os.h:284`）。

### 时间与节流

- `get_ticks_usec()`（`os.h:281`）：单调时钟（微秒），主循环计时基础（见 [01](01-启动与主循环.md)）。
- `delay_usec()`（`os.h:277`）、`add_frame_delay()`（`os.h:278`）：帧延迟，支持低功耗模式与 vsync 协调。
- `is_in_low_processor_usage_mode()`（`os.h:204`）：低功耗模式下减少渲染（`Main::iteration` 据 `has_changed` 决定是否 `draw`，见 [01](01-启动与主循环.md)）。

### 日志与渲染驱动

- `CompositeLogger *_logger`（`os.h:100`）：日志输出（`print`/`printerr`/`print_error`，`os.h:169-172`），支持多目标（stdout、文件、编辑器）。
- `set_current_rendering_driver_name`/`set_current_rendering_method`（`os.h:150-157`）：记录运行时渲染驱动（forward_plus/mobile/gl_compatibility）与来源，供 GDExtension 查询。
- `_separate_thread_render`（`os.h:127`）：渲染是否独立线程。

### Feature 标签

`_check_internal_feature_support`（`os.h:143`）：平台声明能力标签（如 `pc`、`mobile`、`web`），供脚本与项目设置按平台分支。

## DisplayServer 窗口与事件

`DisplayServer`（`servers/display/display_server.h:62 : public Object`）单例，与 `OS` 分工：`OS` 偏底层环境，`DisplayServer` 专注窗口系统、输入事件、剪贴板、光标。`Main::setup2` 创建（`main.cpp:3157`）。

### 核心接口

- **事件泵**：`process_events()`（`display_server.h:119`）--每帧由 `OS::run` 调用，泵送窗口消息（见 [01](01-启动与主循环.md)）。`swap_buffers()`（`display_server.h:123`）交换渲染缓冲。
- **能力**：`has_feature(Feature)`（`display_server.h:117`）：`FEATURE_NATIVE_ICON`/`FEATURE_ICON`/`FEATURE_CURSOR`/`FEATURE_IME`/`FEATURE_HIDPI`/`FEATURE_WINDOW_DRAG` 等，决定哪些 API 可用。
- **窗口**：`window_set_title`/`window_set_size`/`window_set_position`/`window_set_mode`/`window_set_flag`/`window_move_to_foreground`（`display_server.h:399-461`）等数十个窗口操作。
- **回调注册**：`window_set_rect_changed_callback`/`window_set_window_event_callback`/`window_set_input_event_callback`/`window_set_input_text_callback`/`window_set_drop_files_callback`（`display_server.h:391-397`）：`Window` 节点注册回调接收事件。
- **光标/屏幕**：`cursor_set_shape`/`cursor_set_custom_image`（`display_server.h:263-265`）、`screen_set_orientation`/`screen_set_keep_on`（`display_server.h:356-359`）。
- **HDR**：`window_request_hdr_output`/`window_set_hdr_output_reference_luminance`/`..._max_luminance`（`display_server.h:437-441`）：HDR 输出控制。

### 平台后端

- 每平台提供 `DisplayServer_<plat>`（如 `platform/windows/display_server_windows.cpp`），编译时选定，无 Manager 竞争。
- `DisplayServerHeadless`（`display_server_headless.h:38`）：无头模式（服务器/CI）空实现。
- `Window` 节点（scene）是 DisplayServer 窗口的封装，`window_attach_instance_id`（`display_server.h:388`）把窗口与节点关联。

## 内存管理

`core/os/memory.h` 定义引擎统一的内存分配。所有 `Object` 经 `memnew`/`memdelete` 创建销毁（见 [02 对象系统](02-对象系统.md)）。

### 分配原语

- `Memory` 命名空间（`memory.h:96-99`）：`alloc_static`/`realloc_static`/`free_static`（`:65/69/70`）、`alloc_aligned_static`/`free_aligned_static`（`:88/94`，对齐分配用于 SIMD）、统计 `get_mem_usage`/`get_mem_max_usage`。
- `DefaultAllocator`（`memory.h:101`）：默认分配器，`alloc`/`free` 转发 `Memory`。
- `operator new(size, DefaultAllocator)`（`memory.h:110`）：placement new 重载，使 `new (DefaultAllocator{}) T` 走引擎分配器。

### memnew / memdelete 宏

```cpp
#define memnew(m_class) _post_initialize(::new (DefaultAllocator{}) m_class)   // memory.h:148
template <typename T> void memdelete(T *p_class);                              // memory.h:158
```

- `memnew`：placement new + `_post_initialize`（`memory.h:142`）发送 `NOTIFICATION_POSTINITIALIZE`。对 `RefCounted` 子类，`memnew_result` 特化（`memory.h:132` + `ref_counted.h:232`）使返回 `Ref<T>`。
- `memdelete`（`memory.h:158`）：先 `predelete_handler`（发 `NOTIFICATION_PREDELETE`，可拒绝删除），再析构 + `Memory::free_static`。
- `memnew_arr`/`memdelete_arr`（`memory.h:187`）：数组版本，带元素计数头（`DATA_OFFSET`/`ELEMENT_OFFSET`，`memory.h:60-62`）。
- `memnew_placement`（`memory.h:151`）：在预分配内存上构造（如池分配器）。
- `memalloc`/`memrealloc`/`memfree`（`memory.h:126-129`）：C 风格裸分配（非对象）。

### 统计与对齐

DEBUG 下 `Memory` 跟踪分配，`get_mem_usage` 供 `Performance` 单例报告（见 [01](01-启动与主循环.md)）。对齐分配支持 `AlignedAllocator`，用于 SSE/AVX 数据。

## 线程原语

`core/os/thread.h` 与 `core/templates/safe_refcount.h` 提供跨平台线程与原子。

### Thread

`Thread`（`thread.h:64`，多线程版；`:148` 单线程存根版）：

- `get_caller_id()`（`thread.h:124`）：当前线程 ID，用于「主线程检查」。
- `get_main_id()`/`is_main_thread()`（`thread.h:128/130`）：主线程 ID 与判断。`make_main_thread()`（`thread.h:131`）在 `Main::setup` 标记当前线程为主线程（`main.cpp:962`）。
- `MAIN_ID` 固定为 1，`caller_id` 线程局部，`is_main_thread` 仅比较二者（`:130` 注释强调无需校验）。
- `start(callback, userdata)`/`wait_to_finish()`：启动/等待线程。
- 单线程构建（`THREADS_ENABLED` 关闭）时 `Thread` 退化为存根，`is_main_thread()` 恒真（`:192`），保证单线程代码可编译。

### 同步原语（`core/os/`）

| 类 | 文件 | 用途 |
|----|------|------|
| `Mutex` | `mutex.h` | 互斥锁，`MutexLock` RAII |
| `BinaryMutex` | `mutex.h` | 不可递归互斥（更轻） |
| `RWLock` | `rw_lock.h` | 读写锁，`ReadLock`/`WriteLock` |
| `Semaphore` | `semaphore.h` | 信号量，线程间通知 |
| `SpinLock` | `spin_lock.h` | 自旋锁，`ObjectDB` 用（见 [02](02-对象系统.md)） |
| `SafeBinaryMutex` | `safe_binary_mutex.h` | 带标签的二值互斥，资源加载用（见 [05](05-资源系统.md)） |
| `ConditionVariable` | `condition_variable.h` | 条件变量 |

### SafeRefCount / SafeNumeric

`core/templates/safe_refcount.h`：

- `SafeRefCount`：原子引用计数，`reference()`/`unreference()`/`refval()`。`RefCounted` 基础（见 [02](02-对象系统.md)）。
- `SafeNumeric<T>`：通用原子数值，`get`/`set`/`add`/`sub`/`increment`/`decrement`。
- `SafeFlag`：原子布尔（`Thread::is_main_thread_assigned` 用，`thread.h:110`）。
- 底层用 `std::atomic` 或平台 intrinsic。

### _THREAD_SAFE_CLASS_ 宏

`core/os/thread_safe.h:35-36`：

```cpp
#define _THREAD_SAFE_CLASS_   mutable Mutex _thread_safe_;
#define _THREAD_SAFE_METHOD_  MutexLock _thread_safe_method_(_thread_safe_);
```

类声明 `_THREAD_SAFE_CLASS_` 添加成员互斥锁，方法首行 `_THREAD_SAFE_METHOD_` 自动加锁。`SceneTree`（见 [04](04-节点与场景树.md)）等用此模式声明线程安全契约。注意这只是「方法级串行化」，不解决更复杂的多线程设计（如服务器的命令队列模式，见 [06](06-服务器架构.md)）。

### WorkerThreadPool

`WorkerThreadPool`（`core/object/worker_thread_pool.h:44`）是引擎任务并行池，见 [02 对象系统](02-对象系统.md)。用于资源加载、导入、场景树处理组并行等。

## 时间

`Time`（`core/os/time.h`，单例，`register_core_types.cpp:152-153` 注册并实例化）：

- `get_ticks_usec/msec`：单调时钟（多数平台委托 `OS::get_ticks_usec`）。
- `get_unix_time`/`get_datetime`/`get_date_string`：墙钟时间与格式化。
- `get_time_zone_info`：时区。
- 主循环的 `MainTimerSync` 用 `OS::get_ticks_usec` 计算帧步长（见 [01](01-启动与主循环.md)）。

## 输入系统

`core/input/`：

- `Input`（`input.h`，单例）：输入状态聚合，从 `DisplayServer` 接收原始事件，经 `InputMap` 映射为 action，分发到 `Viewport`（见 [04](04-节点与场景树.md)）。
- `InputEvent` 及其子类（`input_event.h`）：`InputEventKey`/`MouseButton`/`MouseMotion`/`JoypadButton`/`JoypadMotion`/`ScreenDrag`/`ScreenTouch`/`Action`/`Gesture`/`MIDI`，在 `register_core_types` 注册（见 [03](03-类型系统与反射.md)）。
- `InputMap`（`input_map.h`）：action 到输入事件的映射，读项目设置 `input/*`。
- 「agile input flushing」：`is_agile_input_event_flushing()`/`flush_buffered_events()`，在 `Main::iteration` 物理循环内与逻辑后各刷一次（见 [01](01-启动与主循环.md)），降低输入延迟。
- 手柄映射：`gamecontrollerdb.txt`/`godotcontrollerdb.txt`（SDL 风格映射）。
- 平台手柄：`OS::initialize_joypads()`（`os.h:133`）。

## 平台层与 detect.py

`platform/` 各目录是一个平台后端：windows、linuxbsd、macos、android、ios、web、visionos。每个含 `detect.py`、`SCsub`、`os_<plat>.cpp`、`display_server_<plat>.cpp`、`api/`（可选导出 API）、`export/`（可选导出器）。

### detect.py

`SConstruct` 启动时遍历 `platform/*`（`SConstruct:77`），导入每个 `detect.py`，调用：

- `get_name()`（如 `detect.py:19` 返回 `"Windows"`）。
- `can_build()`：平台是否可在当前主机构建。
- `get_opts()`：平台构建选项（如 `use_mingw`、`use_static_cpp`）。
- `get_flags()`：平台编译/链接标志。
- `get_doc_classes()`/`get_doc_path()`：平台特有文档类。
- 探测工具链：如 Windows 的 `try_cmd`（`detect.py:23`）探测 MinGW/MSVC/Clang 与架构。

### 平台职责

每个平台实现：

- `OS_<plat>`：`OS` 子类，实现 `initialize`/`finalize`/`run`/`get_ticks_usec`/`get_user_data_dir`/`create_process` 等。
- `DisplayServer_<plat>`：`DisplayServer` 子类，窗口与事件。
- `FileAccess`/`DirAccess`/`Thread`/`Mutex` 后端（多数用 `std` 或 POSIX/Win32）。
- `godot_<plat>.cpp`：`main()` 入口（见 [01](01-启动与主循环.md)）。
- `api/api.cpp`（可选）：平台专用 GDExtension API。
- `export/export.cpp`（可选）：编辑器导出插件（见 [09](09-编辑器架构.md)）。

### 架构无关的抽象

得益于 `OS`/`DisplayServer`/`FileAccess`/`DirAccess`/`Thread` 抽象，`core/`/`scene/`/`servers/`/`editor/` 的绝大多数代码不感知具体平台，仅在 `platform/` 层适配。`#ifdef WINDOWS_ENABLED`/`__APPLE__`/`ANDROID_ENABLED` 等宏用于少量平台特例。

## 与其他子系统关系

- **主循环**：`OS::run` 承载帧循环与事件泵，`OS::get_ticks_usec` 驱动计时，见 [01 启动与主循环](01-启动与主循环.md)。
- **对象系统**：`memnew`/`memdelete` 管理对象生命周期，`SafeRefCount` 支撑 `RefCounted`，`Thread::is_main_thread` 守护节点系统，见 [02 对象系统](02-对象系统.md)。
- **资源系统**：`FileAccess`/`DirAccess` 与 PCK 经 `OS` 路径解析，`open_dynamic_library` 加载 GDExtension，`get_user_data_dir` 定位 `user://`，见 [05 资源系统](05-资源系统.md)。
- **服务器**：`DisplayServer`/`AudioDriver` 是服务器后端，渲染 context 经平台窗口系统，`WorkerThreadPool` 供并行，见 [06 服务器架构](06-服务器架构.md)。
- **构建**：`detect.py` 探测平台与工具链，`SCsub` 组织平台源，见 [10 模块与构建](10-模块与构建.md)。
