# 10 模块与构建

## 职责定位

本章覆盖两件事：**SCons 构建系统**如何把源码编译为引擎可执行文件，以及**模块机制**如何让可选功能以独立单元加入构建与类型注册。理解本章能回答「引擎如何编译、如何增减功能、类型如何按层级注册」。同时涵盖第三方库管理、SCU 构建、代码规范与测试框架。

## SCons 构建系统

Godot 仅用 **SCons**（`SConstruct:4` 要求 SCons 4.4+，Python 3.9+），不支持 CMake/Make。

### 入口 SConstruct

`SConstruct`（1262 行）的职责：

1. **加载辅助模块**（`SConstruct:47-54`）：`gles3_builders`/`glsl_builders`/`methods`/`platform_methods`/`version`/`core.core_builders` 等，用 `_helper_module` 显式解析避免命名冲突。tools 构建（`target=editor`）额外加载 `editor.editor_builders`/`editor.template_builders`（`:64-66`）。
2. **扫描平台**（`:77-109`）：`glob.glob("platform/*")`，对每个含 `detect.py` 的目录导入，调用 `can_build()`/`get_opts()`/`get_flags()`/`get_doc_classes()`/`get_doc_path()`，填充 `platform_list`/`platform_opts`/`platform_flags`。检测 `export/export.cpp` 与 `api/api.cpp` 标记导出器与 API 平台。
3. **解析选项**：`platform=`、`target=`（editor/template_debug/template_release）、`tests=`、`module_<name>=`、`scu_build=` 等。
4. **构建环境**：`env = Environment(tools=[])`（`:115`），按平台 `detect.py` 的 flags 配置编译器/链接器。
5. **递归 SConscript**：按层级调用各目录 `SCsub`（core -> drivers -> servers -> scene -> modules -> editor -> platform -> main）。
6. **生成产物**：输出到 `bin/`，如 `godot.windows.editor.x86_64.exe`。

### 常用目标与命令

```bash
scons platform=windows                    # 默认 editor
scons platform=linuxbsd target=template_release
scons platform=android target=template_debug
scons scu_build=yes                       # SCU 构建
scons module_mono=no                      # 关闭模块
scons tests=yes                           # 启用测试
```

### SCsub 分层

每个目录的 `SCsub` 用 `env.add_source_files(sources, "*.cpp")` 收集源码，构建为静态库。`add_source_files`（`methods.py:35`）支持 glob，但**排除 `.gen.cpp`**（`:42-43`，避免包含过时生成文件，需显式加入）。典型层级：

```
core/SCsub       -> libcore.a
drivers/SCsub    -> libdrivers.a
servers/SCsub    -> libservers.a
scene/SCsub      -> libscene.a
modules/SCsub    -> libmodule_<name>.a (每个模块) + libmodules.a
editor/SCsub     -> libeditor.a (仅 TOOLS_ENABLED)
platform/<plat>/SCsub -> 平台源码
main/SCsub       -> libmain.a
最终链接 -> bin/godot.<plat>.<target>.<arch>[.exe]
```

### 代码生成器

`*_builders.py` 在构建时生成 `.gen.h`/`.gen.cpp`：

- `core_builders.py`：`gdvirtual.gen.h`（GDVIRTUAL 宏展开，见 [03](03-类型系统与反射.md)）、`bind_methods` 等。
- `glsl_builders.py`/`gles3_builders.py`：着色器编译为头/字节码。
- `modules_builders.py`：`modules_enabled.gen.h`（`MODULE_<NAME>_ENABLED` 宏）、`register_module_types.gen.cpp`（聚合各模块注册函数）、`modules_tests.gen.h`。
- `main_builders.py`、`editor_builders.py`、`template_builders.py`：各自生成。

## 模块机制

`modules/` 下每个子目录是一个可选模块（61 个，见 [00 索引](../核心架构.md)），各自独立。

### 模块文件约定

一个模块至少含：

- `config.py`：构建配置。
- `SCsub`：源码组织。
- `register_types.h/.cpp`：类型注册。
- `doc_classes/`（可选）：文档类。
- `config.py` 的 `can_build`/`configure`/`get_doc_classes`/`get_doc_path`。

### config.py（以 gdscript 为例，`modules/gdscript/config.py`）

```python
def can_build(env, platform):
    env.module_add_dependencies("gdscript", ["jsonrpc", "websocket"], True)  # 声明依赖
    return True                       # 所有平台可构建

def configure(env): pass
def get_doc_classes(): return ["@GDScript", "GDScript", ...]
def get_doc_path(): return "doc_classes"
```

- `can_build(env, platform)` 返回 `False` 可在特定平台/条件下禁用模块。
- `module_add_dependencies` 声明模块间依赖，被依赖模块自动启用。
- 命令行 `module_<name>=no` 可手动关闭（生成 `modules_enabled.gen.h` 不含该宏）。

### modules/SCsub（`modules/SCsub`）

- 为每个启用模块 `SConscript(name + "/SCsub")`（`:38`），构建 `libmodule_<name>.a`（`:41`）。
- 生成 `modules_enabled.gen.h`（`:19-21`）含 `#define MODULE_<NAME>_ENABLED`。
- 生成 `register_module_types.gen.cpp`（`:24-28`），聚合所有模块的 `initialize_<name>_module`/`uninitialize_<name>_module` 调用。
- `libmodules.a`（`:62`）只含注册代码，最后链接以正确顺序。

### register_module_types.h（`modules/register_module_types.h`）

```cpp
enum ModuleInitializationLevel {
    MODULE_INITIALIZATION_LEVEL_CORE = GDEXTENSION_INITIALIZATION_CORE,
    MODULE_INITIALIZATION_LEVEL_SERVERS,
    MODULE_INITIALIZATION_LEVEL_SCENE,
    MODULE_INITIALIZATION_LEVEL_EDITOR
};
void initialize_modules(ModuleInitializationLevel p_level);
void uninitialize_modules(ModuleInitializationLevel p_level);
```

`initialize_modules`（生成于 `register_module_types.gen.cpp`）按层级调用每个模块的 `initialize_<name>_module(level)`。与 GDExtension 的 `InitializationLevel` 对齐（见 [08 脚本与扩展](08-脚本与扩展.md)）。

### register_types.cpp（以 gdscript 为例）

每个模块实现 `initialize_<name>_module(ModuleInitializationLevel)` 与 `uninitialize_<name>_module`，按层级分支注册：

```cpp
void initialize_gdscript_module(ModuleInitializationLevel p_level) {
    if (p_level == MODULE_INITIALIZATION_LEVEL_SERVERS) {   // register_types.cpp:139
        GDREGISTER_CLASS(GDScript);
        script_language_gd = memnew(GDScriptLanguage);
        ScriptServer::register_language(script_language_gd);
        ResourceLoader::add_resource_format_loader(resource_loader_gd);
        ...
    }
#ifdef TOOLS_ENABLED
    else if (p_level == MODULE_INITIALIZATION_LEVEL_EDITOR) {
        // 编辑器插件、导出插件、语法高亮...
    }
#endif
}
```

模块在合适的层级注册类型/语言/资源格式/编辑器插件，与引擎自身 `register_*_types` 同步（见下文时序）。

## register_*_types 注册总时序

类型注册按引擎层级在 `Main::setup`/`setup2` 中依次进行（见 [01 启动与主循环](01-启动与主循环.md) 时序表）：

| 顺序 | 调用 | 位置 | 内容 |
|------|------|------|------|
| 1 | `register_core_types()` | `main.cpp:992` | core 层（Object/Variant/Resource，见 `register_core_types.cpp:134`） |
| 2 | `register_core_driver_types()` | `main.cpp:993` | 驱动层 |
| 3 | `register_server_types()` | `main.cpp:3134` | 服务器层接口 |
| 4 | `initialize_modules(SERVERS)` | `main.cpp:3138` | 模块服务器级 |
| 5 | `GDExtensionManager::initialize_extensions(SERVERS)` | `main.cpp:3139` | 扩展服务器级 |
| 6 | `register_scene_types()` + `register_driver_types()` | `main.cpp:3686-3687` | 场景层 |
| 7 | `initialize_modules(SCENE)` | `main.cpp:3694` | 模块场景级 |
| 8 | `GDExtensionManager::initialize_extensions(SCENE)` | `main.cpp:3695` | 扩展场景级 |
| 9 | `register_editor_types()`（tools） | `main.cpp:3713` | 编辑器层 |
| 10 | `initialize_modules(EDITOR)` | `main.cpp:3718` | 模块编辑器级 |
| 11 | `GDExtensionManager::initialize_extensions(EDITOR)` | `main.cpp:3719` | 扩展编辑器级 |

每层注册前 `ClassDB::set_current_api(...)` 设置 API 归属（CORE/EDITOR/EXTENSION，见 [03](03-类型系统与反射.md)）。`unregister_*_types` 在 `Main::cleanup` 按逆序执行（见 [01](01-启动与主循环.md)）。模块与 GDExtension 都在每层级同步初始化/反初始化，保证依赖顺序正确。

## 平台层与 detect.py

`platform/` 各目录含 `detect.py`，职责（见 [07 OS 与平台抽象](07-OS与平台抽象.md)）：

- `get_name()`/`can_build()`/`get_opts()`/`get_flags()`：平台名、可构建性、构建选项（如 `use_mingw`）、编译标志。
- 探测工具链（如 Windows `try_cmd` 探测 MinGW/MSVC/Clang，`detect.py:23`）。
- `get_doc_classes()`/`get_doc_path()`：平台特有文档类。
- 平台 `SCsub` 组织 `os_<plat>.cpp`/`display_server_<plat>.cpp` 等源码。
- `export/export.cpp`（可选）：编辑器导出插件（见 [09](09-编辑器架构.md)）。
- `api/api.cpp`（可选）：平台专用 GDExtension API。

## SCU 构建

`scu_builders.py` 实现 **Single Compilation Unit** 构建（`scons scu_build=yes`）：

- 将多个 `.cpp` 合并为少量「SCU」`.cpp`（每个最多 `_max_includes_per_scu=1024` 个 include，`scu_builders.py:14`），一次编译。
- 大幅减少编译单元数，加快全量编译（代价是增量编译变慢、内存峰值高）。
- `add_source_files_scu`（`methods.py:54`）在 `scu_build` 启用时走 SCU 路径，否则走普通路径。
- 生成的 SCU 文件在 `.scu/` 目录，`clear_out_stale_files`（`scu_builders.py:17`）清理过期文件。

## 第三方库管理

`thirdparty/`（69 个，见 [00 索引](../核心架构.md)）内嵌第三方依赖：

- 源码直接纳入版本控制，排除在 lint/格式化/静态检查之外（`pyproject.toml:16`/`.clang-format`）。

## 代码规范

见 `AGENTS.md` 与配置文件：

- **C++/GLSL**：Tab 缩进，`.clang-format`（LLVM 风格，Tab 4 空格宽，`ColumnLimit: 0` 即不换行）。`.clang-tidy` 静态检查。
- **Python/SConstruct/SCsub**：4 空格缩进，`ruff` 格式化（`pyproject.toml:15`，line-length 120），`mypy` 类型检查（`:1`）。
- **YAML/clang 配置**：2 空格缩进。
- **通用**：LF 换行、UTF-8、末尾换行、去行尾空白（`.editorconfig`）。
- **Include 排序**：clang-format `Regroup` 规则，core/drivers/editor/main/scene/servers/tests -> modules/platform -> thirdparty -> 系统。
- **命名**：参数 `p_` 前缀，成员变量相应前缀。
- `.gen.cpp` 是自动生成的，不纳入 glob，需显式加入构建（`methods.py:42`）。

## Pre-commit（prek）

使用 **`prek`**（非 `pre-commit`），配置在 `.pre-commit-config.yaml`：

- `clang-format`（C++/GLSL）、`ruff-check`/`ruff-format`（Python）、`mypy`、`codespell`（拼写）、`check-jsonschema`。
- `clang-tidy` 仅手动运行（`pre-commit run --hook-stage manual clang-tidy --all`，`.pre-commit-config.yaml:33`）。
- 本地钩子：`make-rst`、`doc-status`、`validate-builders`、`validate-xml`、`validate-codeowners`、`validate-includes`、`eslint`（web 平台 JS）、`jsdoc`、`svgo`（SVG）、`copyright-headers`、`header-guards`、`file-format`、`dotnet-format`（C#）。
- 运行全部：`prek run --all`；CI 调用 `prek run --files ...`。

## 测试框架

- 框架：**doctest**（内嵌 `thirdparty/doctest`）。
- 测试位于 `tests/`，文件 `test_*.cpp`，按子系统分 `tests/core/`、`tests/scene/`、`tests/servers/`、`tests/compatibility_test/`。
- 创建新测试：`python tests/create_test.py <Name> <path>`。
- 每个测试文件须含 `TEST_FORCE_LINK(test_name)` 宏以自动发现。
- 宏：`TEST_CASE`、`TEST_COND`、`TEST_FAIL_COND`、`TEST_CASE_PENDING`（跳过）、`TEST_CASE_MAY_FAIL`。
- 标签触发初始化：`[SceneTree]`、`[Editor]`、`[Audio]`。
- 运行：先构建，再 `./bin/<binary> --test <名称>`；运行跳过的用 `--test --no-skip`。
- 入口 `Main::test_entrypoint`（`main.cpp:907`，见 [01](01-启动与主循环.md)），`test_main` 在 `tests/test_main.cpp`。
- 测试失败路径用 `ERR_PRINT_OFF`/`ERR_PRINT_ON` 屏蔽期望的错误输出。
- 模块测试：`modules/<name>/tests/*.h` 聚合到 `modules_tests.gen.h`（`modules/SCsub:54`）。

## ASCII：构建与注册总览

```
   scons platform=<plat> target=<target>
        │
        ▼
   SConstruct
   ├─ 扫描 platform/*/detect.py (can_build/get_opts/get_flags)
   ├─ 解析选项 (module_*=, tests=, scu_build=)
   ├─ 配置 env (编译器/链接器标志)
   └─ 递归 SConscript 各 SCsub:
        core/ -> libcore.a
        drivers/ -> libdrivers.a
        servers/ -> libservers.a
        scene/ -> libscene.a
        modules/ -> libmodule_<name>.a × N + libmodules.a
              ├─ modules/<name>/config.py (can_build/configure)
              ├─ modules/<name>/SCsub (源码)
              ├─ 生成 modules_enabled.gen.h (MODULE_*_ENABLED)
              └─ 生成 register_module_types.gen.cpp (聚合注册)
        editor/ (TOOLS_ENABLED) -> libeditor.a
        platform/<plat>/ -> 平台源码
        main/ -> libmain.a
        => 链接 bin/godot.<plat>.<target>.<arch>
        │
   运行时注册 (Main::setup/setup2):
   register_core_types -> register_server_types -> initialize_modules(SERVERS)
     -> register_scene_types -> initialize_modules(SCENE)
     -> register_editor_types -> initialize_modules(EDITOR)
   每层同步 GDExtensionManager::initialize_extensions
```

## 与其他子系统关系

- **全章**：构建系统编译所有层，注册时序串联 core/servers/scene/editor 与模块/扩展，是其他所有章的基础。
- **主循环**：`register_*_types` 与 `initialize_modules` 在 `Main::setup`/`setup2` 中按层级调用，见 [01 启动与主循环](01-启动与主循环.md)。
- **类型系统**：`GDREGISTER_*` 宏与 `register_*_types` 把类型注册到 ClassDB，`modules_enabled.gen.h` 的 `MODULE_*_ENABLED` 驱动 `GD_IS_CLASS_ENABLED` 编译期判断，见 [03 类型系统与反射](03-类型系统与反射.md)。
- **脚本/扩展**：GDScript/Mono 是模块，GDExtension 在每层级与模块同步初始化，见 [08 脚本与扩展](08-脚本与扩展.md)。
- **服务器**：物理/文本/导航/XR 的实际后端多在模块中，经 `MODULE_INITIALIZATION_LEVEL_SERVERS` 注册，见 [06 服务器架构](06-服务器架构.md)。
- **OS/平台**：`detect.py` 探测平台与工具链，平台 `SCsub` 提供后端源码，见 [07 OS 与平台抽象](07-OS与平台抽象.md)。
- **编辑器**：编辑器代码仅 `TOOLS_ENABLED`，`register_editor_types` 在 EDITOR 层，见 [09 编辑器架构](09-编辑器架构.md)。
