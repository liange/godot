# 02 对象系统

## 职责定位

对象系统是 Godot 引擎的基石。引擎中几乎所有运行时实体（节点、资源、服务器对象、脚本对象……）都派生自 `Object`。它提供：唯一标识与全局实例表、反射式属性/方法访问、`notification` 消息分发、信号-连接机制、统一的 `Callable` 可调用抽象、跨帧延迟调用队列，以及引用计数内存管理。

对象系统位于 `core/object/`，是 [类型系统](03-类型系统与反射.md) 与 [节点/资源](04-节点与场景树.md) 的共同基础。

## Object 基类

`Object`（`core/object/object.h:355`）是万物之基。核心成员（`object.h:434-444`）：

```cpp
ObjectID _instance_id;
uint32_t _ancestry : 15;      // AncestralClass 位域，快速类型判断
bool _block_signals : 1;
bool _can_translate : 1;
bool _emitting : 1;
bool _predelete_ok : 1;
```

### 生命周期与全局 ID

- 构造时 `_initialize()` 分配 `ObjectID`，`postinitialize_handler` 发送 `NOTIFICATION_POSTINITIALIZE=0`（`object.h:665`）。`memnew` 宏封装此流程。
- 析构前 `_predelete()` 发送 `NOTIFICATION_PREDELETE=1` 让对象清理；析构末尾 `NOTIFICATION_PREDELETE_CLEANUP=3`（`object.h:665-669`）。
- `predelete_handler`/`postinitialize_handler`（`object.h:858-859`）是 `memnew`/`memdelete` 与对象生命周期的接缝。

### AncestralClass 快速类型判断

为避免热路径上的虚函数/字符串比较，`Object` 在每个对象上存一个 15 位 `AncestralClass` 位域（`object.h:371-389`）：

```cpp
enum class AncestralClass : unsigned int {
    REF_COUNTED = 1 << 0,  NODE = 1 << 1,  RESOURCE = 1 << 2,  SCRIPT = 1 << 3,
    CANVAS_ITEM, CONTROL, NODE_2D, COLLISION_OBJECT_2D, AREA_2D,
    NODE_3D, VISUAL_INSTANCE_3D, GEOMETRY_INSTANCE_3D, COLLISION_OBJECT_3D, ...
};
```

- `is_ref_counted()`（`object.h:850`）等常用判断只需一次位与 `_has_ancestry(...)`。
- `cast_to<T>`（`object.h:642`）基于 `derives_from<T,O>`（`object.h:862`）：若 `T` 有显式 `static_ancestral_class` 则用位域判断，否则回退到静态类指针比较。这是一种比 `dynamic_cast` 快得多的「无虚继承」向下转型。

### 反射式访问

`Object` 暴露统一的字符串 API（`object.h:695-710`）：

- `set/get`、`set_indexed/get_indexed`：属性读写，由 `ClassDB` 与脚本实例共同支持（见 [03 类型系统与反射](03-类型系统与反射.md)）。
- `get_property_list`：枚举属性（含动态属性），驱动编辑器面板与序列化。
- `callp`/`callv`/`call`：动态方法调用，转发到 `ClassDB` 或脚本。
- `has_method`/`get_method_list`。

### notification 消息分发

`notification(int p_notification, bool p_reversed=false)`（`object.h:727`）是引擎内最通用的消息通道。它调用虚函数 `_notification_forward` 或 `_notification_backward`（`object.h:724-726` 注释）：

- **Forward**（默认）：`Object -> Node -> Node3D -> extension -> script`（基类先收到）。
- **Backward**（`p_reversed=true`）：`script -> extension -> Node3D -> Node -> Object`（派生类先收到）。

各子系统约定自己的 notification 常量段（如 `Node` 的 `NOTIFICATION_ENTER_TREE` 等，见 [04 节点与场景树](04-节点与场景树.md)；`MainLoop` 的应用级通知见 [01 启动与主循环](01-启动与主循环.md)）。

## ObjectID 与 ObjectDB

`ObjectID`（`core/object/object_id.h:41`）是 64 位整数，最高位标记是否为 `RefCounted`（`is_ref_counted()`，`object_id.h:45`），可与 `int64` 互转以便存入 `Variant`。

`ObjectDB`（`core/object/object.h:880`）是全局实例表，采用**槽位+校验器**设计而非简单哈希表：

```cpp
#define OBJECTDB_VALIDATOR_BITS 39
#define OBJECTDB_SLOT_MAX_COUNT_BITS 24
struct ObjectSlot {              // 128 bits/slot
    uint64_t validator : 39;     // 每次复用槽位递增，避免悬垂引用
    uint64_t next_free : 24;
    uint64_t is_ref_counted : 1;
    Object *object;
};
```

- `add_instance`/`remove_instance`（`object.h:905-906`）在对象构造/析构时维护。
- `get_instance(ObjectID)`（`object.h:914`）：从 `ObjectID` 解析槽位与校验器，`SpinLock` 保护下查 `Object*`。校验器不匹配返回 `nullptr`，因此用旧 ID 查已销毁对象是安全的。
- 这套设计支持约 1600 万并发对象，且 ID 复用安全。

## RefCounted 与 Ref\<T\>

`Object` 默认由调用方手动 `memdelete`。需要自动生命周期管理的类型派生自 `RefCounted`（`core/object/ref_counted.h:36 : public Object`）：

```cpp
class RefCounted : public Object {
    SafeRefCount refcount;        // 原子引用计数
    SafeRefCount refcount_init;   // 初始化态标记
    SafeNumeric<uint32_t> dereference_count;
    bool init_ref();
    bool reference();   // 计数+1，返回 false 表示已归零
    bool unreference(); // 计数-1，返回 true 表示应释放
};
```

- `reference()`/`unreference()` 是**原子**操作（`SafeRefCount`），故 `RefCounted` 可跨线程共享。
- `is_referenced()`（`ref_counted.h:48`）区分「是否已被 Ref 持有」，解决「栈上对象 vs 堆上对象」的初始化歧义。

`Ref<T>`（`ref_counted.h:59`）是 `RefCounted` 的智能指针：

- 构造/赋值调用 `reference()`，析构/重赋值调用 `unref()`（`ref_counted.h:199`）；`unreference()` 返回 true 时 `memdelete`。
- `ref_pointer<Init>`（`ref_counted.h:67`）处理首次 `init_ref` 与后续 `reference` 的区别。
- `instantiate()`（`ref_counted.h:216`）等价于 `Ref<T> r; r.instantiate();`，内部 `memnew(T)`。
- `Ref<T>` 可隐式转 `Variant`（`ref_counted.h:129`），是脚本侧持有资源的标准形式。
- `memnew_result` 特化（`ref_counted.h:232`）使 `memnew(RefCounted子类)` 直接返回 `Ref<T>`，避免误漏引用。

> 内存分配原语 `memnew`/`memdelete`/`memnew_arr` 等定义在 `core/os/memory.h`，见 [07 OS 与平台抽象](07-OS与平台抽象.md)。

## 信号与连接

`Object` 内置信号系统，数据结构（`object.h:417-430`）：

```cpp
struct SignalData {
    struct Slot { int reference_count; Connection conn; ... };
    MethodInfo user;                       // 信号元信息
    HashMap<Callable, Slot> slot_map;      // 连接表
    bool removable;
};
mutable Mutex *signal_mutex;
HashMap<StringName, SignalData> signal_map;  // 按信号名索引
List<Connection> connections;                // 本对象作为接收方的连接
```

- `connect(signal, callable, flags)`（`object.h:791`）、`disconnect`、`is_connected`、`emit_signal`（`object.h:773`）。
- 连接标志 `ConnectFlags`（`object.h:359`）：`CONNECT_DEFERRED`（经 MessageQueue 延迟触发）、`CONNECT_PERSIST`（场景保存时持久化）、`CONNECT_ONE_SHOT`（触发一次后断开）、`CONNECT_REFERENCE_COUNTED`（多次 connect 需多次 disconnect）。
- `Connection`（`object.h:393`）：`{ Signal signal, Callable callable, uint32_t flags }`。
- `Signal`（`core/variant/callable.h:178`）：`{ StringName name, ObjectID object }` 的轻量代理，可放入 `Variant`，供脚本语言使用；`Signal::emit/connect/disconnect` 转发回所属 `Object`。

### Callable 统一可调用抽象

`Callable`（`core/variant/callable.h:48`）是「可被调用之物」的统一抽象，被信号、`call_deferred`、`Tween`、`WorkerThreadPool` 等广泛使用。设计为 16 字节：

```cpp
class Callable {
    alignas(8) StringName method;
    union { uint64_t object; CallableCustom *custom; };
};
```

两种形态：
- **标准 Callable**（`is_standard()`，`callable.h:95`）：`{ object, method }`，调用时经 `Object::callp` -> `ClassDB`/脚本。
- **自定义 Callable**（`is_custom()`，`callable.h:92`）：持有 `CallableCustom*`（`callable.h:143`，引用计数虚基类），用于闭包、`callable_mp`（C++ 方法指针绑定，`core/object/callable_mp.h`）、lambda 等。

能力：`call`/`callp`/`call_deferred`、`bind`/`unbind`（参数柯里化）、`rpcp`（网络 RPC）、`hash`、`CallError` 错误回报（`callable.h:56`）。`Callable` 让「对象方法」「C++ 函数」「脚本闭包」在引擎 API 中以同一类型出现。

## MessageQueue 延迟调用

`CallQueue`/`MessageQueue`（`core/object/message_queue.h:41/150`）实现跨帧延迟调用，是「线程/回调安全地触碰主线程对象」的核心机制。

- 分页存储：`Page` 4096 字节（`message_queue.h:46`），`LocalVector<Page*>` 链式增长，`PagedAllocator` 复用。
- 消息类型（`message_queue.h:58-66`）：`TYPE_CALL`、`TYPE_NOTIFICATION`、`TYPE_SET`，带 `FLAG_NULL_IS_OK`/`FLAG_SHOW_ERROR`。
- 入队 API（`message_queue.h:107-135`）：`push_callp`（按 `ObjectID` 或 `Object*`）、`push_callablep`、`push_set`、`push_notification`。
- `flush()`：在主循环内被调用（见 [01 启动与主循环](01-启动与主循环.md) 的 `iteration`），顺序执行队列中的调用。
- 单例：`MessageQueue::get_singleton()` 优先返回线程局部 `thread_singleton`，否则主单例（`message_queue.h:156`）。

### Object 上的延迟接口

`Object` 提供便捷封装（`object.h:796-807`）：

- `call_deferred(method, args...)`：等价 `MessageQueue::push_call`。
- `set_deferred(prop, value)`：延迟属性写，避免在信号回调中同步修改导致的状态不一致。

典型用途：物理回调里 `call_deferred("queue_free")`、信号触发 `CONNECT_DEFERRED` 连接、节点 `set_deferred` 安全修改。延迟调用让「修改对象树」「触发信号」等操作推迟到帧的安全点执行。

## WorkerThreadPool

`WorkerThreadPool`（`core/object/worker_thread_pool.h:44 : public Object`）是引擎自带的任务并行线程池，单例。

- `TaskID add_task(Callable, high_priority, description)`（`worker_thread_pool.h:246`）：提交一次性任务。
- `add_native_task`/`add_template_task`：C 函数指针 / 成员函数指针变体（`worker_thread_pool.h:245/237`）。
- `wait_for_task_completion(TaskID)`（`worker_thread_pool.h:250`）：阻塞等待。
- `Group` API（`worker_thread_pool.h:154` 附近）：`add_group_task` 分发批量并行任务，`wait_for_group_completion` 汇合。
- 内部 `Task` 结构（`worker_thread_pool.h:74`）维护状态机与 `TaskID` 自引用，支持任务 yield。

`WorkerThreadPool` 用于资源加载、导入、导航烘焙等可并行工作，与 `MessageQueue` 配合：工作线程计算，结果通过 `call_deferred` 回主线程。

## 脚本实例挂载

`Object` 可挂载一个 `ScriptInstance`（`object.h:767` `set_script_instance`/`get_script_instance`）。脚本语言通过 `ScriptInstance` 把脚本方法/属性接入 `Object` 的 `callp`/`set`/`get` 链。这使得任意 `Object` 都可被脚本「附加」行为，是 [08 脚本与扩展](08-脚本与扩展.md) 的基础。`Object::callp` 的派发顺序通常是：先脚本实例，再 `ClassDB`。

## 与其他子系统关系

- **类型系统**：`Object::callp`/`set`/`get` 依赖 `ClassDB` 反射派发，`AncestralClass` 由 `GDCLASS` 宏设置，见 [03 类型系统与反射](03-类型系统与反射.md)。
- **节点/资源**：`Node`/`Resource` 都派生自 `Object`（`Resource` 经 `RefCounted`），靠 `notification` 与 `ObjectID` 串联，见 [04 节点与场景树](04-节点与场景树.md)、[05 资源系统](05-资源系统.md)。
- **主循环**：`MessageQueue::flush()` 在 `iteration` 中执行，`set_current_thread_safe_for_nodes` 标记主线程，见 [01 启动与主循环](01-启动与主循环.md)。
- **脚本**：`ScriptInstance` 让脚本行为接入 `Object`，`Callable` 统一脚本闭包与 C++ 方法，见 [08 脚本与扩展](08-脚本与扩展.md)。
