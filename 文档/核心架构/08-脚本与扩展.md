# 08 脚本与扩展

## 职责定位

脚本与扩展系统让用户用非 C++ 语言为引擎编写逻辑与定义类型。Godot 提供统一的脚本语言抽象（`ScriptLanguage`/`ScriptInstance`/`Script`），内置 GDScript（`modules/gdscript`），可选 C#（`modules/mono`），并通过 GDExtension（C ABI）允许外部原生库注册引擎类型。脚本经反射（见 [03](03-类型系统与反射.md)）与 `Variant` 互操作，可附加到任意 `Object`（见 [02](02-对象系统.md)），实现跨语言一致的对象模型。

## 脚本语言抽象

### ScriptServer（`core/object/script_language.h:50`）

`ScriptServer` 是脚本系统全局管理器（全静态），管理多语言共存：

- `_languages[MAX_LANGUAGES=16]`（`script_language.h:55`）：已注册语言数组。
- `register_language`/`unregister_language`（`script_language.h:82-83`）：语言注册。`get_language_count`/`get_language`/`get_language_for_extension`（`:79-81`）查询。
- `global_classes`（`script_language.h:72`）：全局脚本类注册表（`GlobalScriptClass`，`:64-70`，含语言/路径/基类/是否抽象/是否 tool）。`add_global_class`/`is_global_class`/`get_global_class_path`/`get_global_class_base`（`:92-99`）维护，支持脚本类按名字实例化（如 `start()` 中 `main_loop_type` 解析，见 [01](01-启动与主循环.md)）。
- `init_languages()`（`:109`）：启动时初始化所有语言。
- `thread_enter`/`thread_exit`（`:88-89`）：线程TLS。
- `capture_script_backtraces`（`:107`）：捕获脚本调用栈（用于崩溃报告）。

### ScriptLanguage（`script_language.h:212 : public Object`）

脚本语言基类，每种语言实现一个子类：

- `init()`（`:222`）：语言初始化。
- `frame()`（`:427`）：每帧由 `Main::iteration` 调用所有语言（见 [01](01-启动与主循环.md)），做帧清理（如 GDScript 的临时字符串、GC 增量）。
- `make_template`/`get_global_class_name`（`:285/430`）：模板生成与文件->类名解析（供 `EditorFileSystem` 扫描）。
- 代码补全/校验/调试：`_complete_code`/`_validate`/`_lookup_code`/`_debug_get_*`（见 `ScriptLanguageExtension`）。
- `get_recognized_extensions`：该语言处理的文件扩展名。

### Script（`script_language.h:117 : public Resource`）

`Script` 是脚本资源基类（派生自 `Resource`，见 [05](05-资源系统.md)），代表「一段可附加到对象的脚本代码」：

- `get_base_script()`（`:151`）：脚本继承链。
- `can_instantiate()`/`instance_create(Object *)`：实例化脚本，返回 `ScriptInstance`。
- `get_base_type()`：脚本继承的原生基类（如 `Node`）。
- `get_script_method_list`/`get_script_property_list`/`get_script_signal_list`：脚本定义的方法/属性/信号（反射，见 [03](03-类型系统与反射.md)）。
- `get_instance_base_type`：无脚本实例时的回退类型。
- `Script` 是 `Resource`，可被 `ResourceLoader` 加载（脚本语言注册对应的 `ResourceFormatLoaderScript`）。

### ScriptInstance（`script_instance.h:38`）

`ScriptInstance` 是脚本「附加到某个 `Object` 的实例」的接口，是脚本与对象系统的接缝（见 [02 对象系统](02-对象系统.md)）：

```cpp
class ScriptInstance {
    virtual bool set(const StringName &p_name, const Variant &p_value) = 0;   // script_instance.h:40
    virtual bool get(const StringName &p_name, Variant &r_ret) const = 0;
    virtual void get_property_list(List<PropertyInfo> *) const = 0;
    virtual Variant::Type get_property_type(const StringName &, bool *) const = 0;
    virtual void validate_property(PropertyInfo &) const = 0;
    virtual Variant callp(const StringName &p_method, const Variant **p_args, int p_argcount, CallError &r_error) = 0;  // :57
    virtual void notification(int p_notification, bool p_reversed = false) = 0;  // :71
    virtual Object *get_owner();                    // :49 持有此实例的 Object
    virtual Ref<Script> get_script() const = 0;
    virtual bool property_can_revert/property_get_revert;  // 编辑器还原
    virtual void refcount_incremented/refcount_decremented();  // :83-84 自管引用计数
    virtual const Variant get_rpc_config() const;   // :93 RPC 配置
    virtual ScriptLanguage *get_language() = 0;
};
```

`Object::set_script_instance`（见 [02](02-对象系统.md)）挂载 `ScriptInstance`。之后 `Object::callp`/`set`/`get`/`get_property_list`/`notification` 会先尝试 `ScriptInstance`，再回退 `ClassDB`。这使得脚本方法、脚本属性、脚本 `_notification` 处理透明接入 `Object`。`refcount_incremented/decremented` 让自管 GC 的语言（如 C#）干预 `RefCounted` 生命周期。

### PlaceHolderScriptInstance（`script_language.h:439`）

占位脚本实例：脚本尚未编译完成或加载失败时使用，保留属性默认值，使编辑器仍能显示属性。编辑器中常见（脚本有语法错误时节点仍可编辑属性）。

## GDScript（`modules/gdscript`）

GDScript 是 Godot 原生脚本语言，Python 风格、静态类型、与引擎深度集成。

### 管线组成

| 文件 | 职责 |
|------|------|
| `gdscript_tokenizer.h/.cpp` | 词法分析 |
| `gdscript_tokenizer_buffer.h/.cpp` | 缓存 token（用于字节码） |
| `gdscript_parser.h/.cpp` | 语法分析，构建 AST |
| `gdscript_analyzer.h/.cpp` | 类型推断与语义分析 |
| `gdscript_compiler.h/.cpp` | AST -> 字节码/函数 |
| `gdscript_byte_codegen.h/.cpp` | 字节码生成 |
| `gdscript_function.h/.cpp` | 字节码函数表示 |
| `gdscript_vm.h/.cpp` | 字节码虚拟机，解释执行 |
| `gdscript_cache.h/.cpp` | 脚本缓存（避免重复解析） |
| `gdscript.h/.cpp` | `GDScript`（Script 子类）、`GDScriptLanguage` |
| `gdscript_resource_format.h/.cpp` | `.gd` 资源格式加载/保存 |
| `gdscript_lambda_callable.h/.cpp` | Lambda -> `CallableCustom` |
| `gdscript_rpc_callable.h/.cpp` | RPC -> `CallableCustom` |
| `register_types.cpp` | 模块注册 `GDScriptLanguage` 与资源格式 |

### 执行模型

GDScript 编译为字节码，由 `gdscript_vm.cpp` 的栈式虚拟机解释执行（`GDScriptFunction::call`）。`GDVIRTUAL` 宏（见 [03](03-类型系统与反射.md)）让脚本覆写 C++ 虚方法（如 `_process`/`_ready`），经 `GDVIRTUAL_CALL` 派发（见 [04](04-节点与场景树.md)）。`GDScript` 经 `ScriptServer::register_language` 注册为 `.gd` 扩展的处理语言。

### 编辑器集成

`modules/gdscript/editor/` 含语法高亮、代码补全、LSP 语言服务器（`language_server/`），通过 `ScriptLanguageExtension` 接口接入编辑器。`gdscript_editor.cpp` 处理脚本热重载、文档生成。

## C# / Mono（`modules/mono`）

C# 绑定经 Mono 运行时实现，是可选模块（`module_mono=yes`）。

### 组成

- `csharp_script.h/.cpp`：`CSharpScript`（`Script` 子类）、`CSharpInstance`（`ScriptInstance` 子类）、`CSharpLanguage`。
- `csharp_script_resource_format.h/.cpp`：`.cs` 与 `.res`（编译产物）资源格式。
- `mono_gc_handle.h/.cpp`：C# 对象 GC 句柄桥接，`refcount_decremented` 让 Mono GC 管理 `RefCounted`。
- `managed_callable.h/.cpp`：C# 委托 -> `CallableCustom`。
- `glue/`：绑定胶水代码（从 `extension_api.json` 生成绑定）。
- `class_db_api_json.cpp`：导出 ClassDB 为 JSON 供绑定生成。
- `editor/`：C# 项目生成、构建、调试集成。
- `build_scripts/`、`Directory.Build.props`：MSBuild 集成。

### 执行模型

C# 编译为 IL，由 Mono JIT 执行。`CSharpInstance::callp` 经绑定调用 C# 方法。C# 对象经 `mono_gc_handle` 与 `RefCounted` 协同生命周期。C# 可注册 `Script` 子类，与 GDScript 平等接入脚本抽象。

## GDExtension 原生扩展

GDExtension 是 Godot 的 **C ABI**，允许用 C/C++（或经绑定的其他语言）编写的原生库加载进引擎并注册类型，无需重编译引擎。这是第三方库集成与高性能扩展的标准方式。

### GDExtension（`core/extension/gdextension.h:39 : public Resource`）

`GDExtension` 是扩展资源，代表「一个已加载的扩展库」：

- `loader`（`gdextension.h:44`）：`GDExtensionLoader` 抽象（策略模式），决定如何加载库。
- `open_library(path, loader)`（`:139`）：打开库（`OS::open_dynamic_library`，见 [07](07-OS与平台抽象.md)）。
- `InitializationLevel`（`:143-147`）：`CORE`/`SERVERS`/`SCENE`/`EDITOR` 四级，与 `register_*_types` 对应（见 [01](01-启动与主循环.md)）。
- `reloadable`/`is_reloading`/`prepare_reload`/`finish_reload`（`:46/105/116-117`）：编辑器热重载支持。
- `GDExtension` 是 `Resource`，可被 `.gdextension` 文件（经 `GDExtensionResourceLoader`）加载，也可在项目设置中声明为 `autoload` 启动加载。

### GDExtensionLoader（`core/extension/gdextension_loader.h`）

加载器抽象：

- `GDExtensionLibraryLoader`（`gdextension_library_loader.h`）：标准动态库加载器，加载 `.dll`/`.so`/`.dylib`，调用入口函数 `gdextension_entry`。
- 自定义 loader：支持非动态库来源（如内嵌、静态链接、从内存加载），`GDExtensionManager::load_extension_with_loader`（见下）。

### C ABI：gdextension_interface

`core/extension/gdextension_interface.cpp` 实现 C ABI，`gdextension_interface.json`（schema `gdextension_interface.schema.json`）定义全部接口函数。扩展库通过「入口函数」获取函数指针表：

- `gdextension_get_proc_address(name)`（`gdextension_interface.cpp:238`）：按名查接口函数指针，供扩展调用引擎。
- `REGISTER_INTERFACE_FUNC(m_name)`（`:1709`）：注册每个接口函数。
- 接口覆盖：内存分配、Variant 操作、ClassDB 注册（`GDExtensionClassCreationInfo`，定义于 `object.h` 的 `ObjectGDExtension`）、对象创建/调用、字符串/数组/字典操作、服务器访问等。
- 版本与 ABI 校验：`ClassDB::get_api_hash`（见 [03](03-类型系统与反射.md)）让扩展在加载时校验引擎 ABI 兼容。

入口函数签名 `GDExtensionInitializationFunction` 接收 `GDExtensionInitialization` 结构，含 `initialize`/`deinitialize` 回调与 `userdata`，引擎按 `InitializationLevel` 调用（见下）。

### ObjectGDExtension（`object.h` 顶部，见 [02](02-对象系统.md)）

GDExtension 注册的类在 `ClassDB` 中以 `ObjectGDExtension` 元信息存在（`class_db.h:126`），含创建/释放/虚方法/set/get 等函数指针。`ClassDB::instantiate` 对扩展类调用 `create_instance3` 创建实例，`Object::_extension_instance` 持有扩展侧实例指针。扩展类与原生类在 ClassDB 中平等，可被脚本继承、编辑器编辑。

### ScriptInstanceExtension（`script_language_extension.h:758`）

GDExtension 脚本实例：`ScriptInstance` 的扩展实现，持有 `GDExtensionScriptInstanceDataPtr` 与 `GDExtensionScriptInstanceInfo3` 函数指针表（`set_func`/`get_func`/`call_func`/...），把 `ScriptInstance` 调用转发回扩展库。这让 GDExtension 可实现完整脚本语言（如其他语言的 Godot 绑定）。

### ScriptExtension / ScriptLanguageExtension

`ScriptExtension`（`script_language_extension.h:43 : public Script`）与 `ScriptLanguageExtension`（`:237 : public ScriptLanguage`）用 `GDVIRTUAL` 把 `Script`/`ScriptLanguage` 的虚方法暴露给脚本/GDExtension 覆写（如 `_get_method_info`/`_validate`/`_complete_code`/`_get_recognized_extensions`）。这让 GDExtension 或 GDScript 自身可实现新的脚本语言或扩展现有语言行为，无需 C++ 编译。C# 与 GDScript 的部分行为也经此抽象接入。

### GDExtensionManager（`gdextension_manager.h:38 : public Object`）

扩展管理单例：

- `load_extension(path)`/`load_extension_with_loader`/`load_extension_from_function`（`:71-73`）：加载扩展。
- `reload_extension(path)`（`:74`）：热重载（编辑器）。
- `unload_extension`（`:75`）：卸载。
- `LoadStatus`（`:53`）：加载状态枚举。
- `initialize_extensions(level)`/`deinitialize_extensions(level)`（`:83-84`）：按层级初始化/反初始化，由 `Main::setup2` 在每层 `register_*_types` 后调用（`main.cpp:3139/3695/3719`，见 [01](01-启动与主循环.md)）。
- `load_extensions`/`reload_extensions`（`:93-94`）：启动时加载项目设置声明的扩展。
- `frame()`（`:99`）：每帧由 `Main::iteration` 调用（见 [01](01-启动与主循环.md)），处理帧级任务。
- `startup()`（在 `Main::start` 末尾 `main.cpp:4754` 调用）：启动已加载扩展。

### 初始化时序

扩展的 `initialize`/`deinitialize` 按 `CORE`->`SERVERS`->`SCENE`->`EDITOR` 层级调用，与引擎自身 `register_*_types` 同步（见 [01](01-启动与主循环.md) 时序表）。这使得扩展能在正确层级注册类型（如服务器级扩展在 `SERVERS` 层注册，编辑器插件在 `EDITOR` 层注册）。`EDITOR` 层仅在 tools 构建下初始化。

## 脚本如何与引擎互操作

1. **方法调用**：`Object::callp(method, args)` -> 先 `ScriptInstance::callp`（脚本方法），失败回退 `ClassDB`（原生方法）。`Callable`（见 [02](02-对象系统.md)）统一脚本闭包与原生方法。
2. **属性访问**：`Object::set/get` -> 先 `ScriptInstance::set/get`（含动态属性），再 `ClassDB` 的 `PropertySetGet`。
3. **属性列表**：`Object::get_property_list` 经 `GDCLASS` 的 `_get_property_listv`（见 [03](03-类型系统与反射.md)）合并 ClassDB 属性 + `ScriptInstance::get_property_list`（脚本声明的导出属性）。
4. **虚方法覆写**：`GDVIRTUAL_CALL` 检查脚本是否覆写并调用（见 [03](03-类型系统与反射.md)、[04](04-节点与场景树.md) 的 `_process`/`_ready`）。
5. **信号**：脚本 `connect`/`emit_signal` 经 `Object` 信号系统（见 [02](02-对象系统.md)），`Callable` 可指向脚本方法。
6. **Variant 桥接**：所有跨边界数据以 `Variant` 传递（见 [03](03-类型系统与反射.md)），脚本语言负责 Variant↔原生类型转换。
7. **RPC**：`Callable::rpcp` + `ScriptInstance::get_rpc_config`（`script_instance.h:93`）支持脚本方法网络调用（`modules/multiplayer`）。
8. **每帧清理**：`Main::iteration` 末 `ScriptServer::get_language(i)->frame()`（见 [01](01-启动与主循环.md)）让各语言做帧清理。

```
   (modules/gdscript)(modules/mono)      (core/extension/)

        │  经 Variant 与 ClassDB 反射互操作

```

## 与其他子系统关系

- **对象系统**：`ScriptInstance` 挂载到 `Object`，`Callable` 统一脚本闭包，`refcount_decremented` 协同 GC，见 [02 对象系统](02-对象系统.md)。
- **类型系统**：`GDVIRTUAL` 让脚本覆写虚方法，脚本属性经 `get_property_list` 接入反射，GDExtension 经 `ObjectGDExtension` 注册类，见 [03 类型系统与反射](03-类型系统与反射.md)。
- **节点/场景树**：节点 `_process`/`_ready` 等经脚本覆写，脚本可作为 `PackedScene` 附加，见 [04 节点与场景树](04-节点与场景树.md)。
- **资源系统**：`Script` 是 `Resource`，由 `ResourceFormatLoaderScript` 加载，GDExtension 经 `.gdextension` 文件加载，见 [05 资源系统](05-资源系统.md)。
- **主循环**：`ScriptServer::frame` 每帧调用，扩展按层级初始化，`GDExtensionManager::frame`/`startup`，见 [01 启动与主循环](01-启动与主循环.md)。
- **编辑器**：脚本语言经 `ScriptLanguageExtension` 接入补全/校验/调试，GDExtension 可注册编辑器插件，见 [09 编辑器架构](09-编辑器架构.md)。
- **模块/构建**：GDScript、Mono 是可选模块（`module_gdscript`/`module_mono`），GDExtension 是核心层特性，见 [10 模块与构建](10-模块与构建.md)。
