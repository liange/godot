# 04 节点与场景树

## 职责定位

节点与场景树是 Godot 表达游戏世界的核心范式：游戏由 `Node` 组成的树来表达，`SceneTree` 作为主循环驱动整棵树的处理。节点提供生命周期、处理回调、分组、输入、暂停、变换、引用关系；场景可序列化为 `PackedScene`（`.tscn`）实现数据驱动与组合复用。本章聚焦 `scene/main/` 中的基础设施，2D/3D/GUI 等具体节点类型是其派生。

## Node 节点基类

`Node`（`scene/main/node.h:54 : public Object`）是所有场景节点的基类。它派生自 `Object`（非 `RefCounted`，由父节点/树管理生命周期），并设置 `AncestralClass::NODE`（见 [02 对象系统](02-对象系统.md)）。

### notification 生命周期

`Node` 不用大量虚函数表达生命周期，而是用统一的 `notification(int)` 通道（见 [02](02-对象系统.md)）。`Node::_notification`（`node.cpp:68`）是一个 switch，把 notification 常量映射到对应行为并 `GDVIRTUAL_CALL` 派发到脚本虚函数。关键常量（`node.h:457-514`）：

| 常量 | 值 | 含义 / 脚本虚函数 |
|------|----|------|
| `NOTIFICATION_ENTER_TREE` | 10 | 节点进入场景树 → `_enter_tree` |
| `NOTIFICATION_EXIT_TREE` | 11 | 节点离开场景树 → `_exit_tree` |
| `NOTIFICATION_READY` | 13 | 节点就绪（子节点已全部 ready）→ `_ready` |
| `NOTIFICATION_PAUSED`/`UNPAUSED` | 14/15 | 暂停状态变化 |
| `NOTIFICATION_PHYSICS_PROCESS` | 16 | 物理处理 → `_physics_process` |
| `NOTIFICATION_PROCESS` | 17 | 逻辑处理 → `_process` |
| `NOTIFICATION_PARENTED`/`UNPARENTED` | 18/19 | 被 add_child / remove_child |
| `NOTIFICATION_SCENE_INSTANTIATED` | 20 | 作为 PackedScene 实例化完成 |
| `NOTIFICATION_CHILD_ORDER_CHANGED` | 24 | 子节点顺序变化 |
| `NOTIFICATION_INTERNAL_PROCESS`/`INTERNAL_PHYSICS_PROCESS` | 25/26 | 内部处理（不暴露给脚本） |
| `NOTIFICATION_POST_ENTER_TREE` | 27 | enter_tree 全树传播后 |
| `NOTIFICATION_DISABLED`/`ENABLED` | 28/29 | process_mode 变为禁用/启用 |
| `NOTIFICATION_WM_*` | 1002+ | 窗口事件（鼠标进入、关闭请求、尺寸变化等） |
| `NOTIFICATION_APPLICATION_PAUSED`/`RESUMED` | 2014/2015 | 应用级暂停/恢复（与 MainLoop 共享） |
| `NOTIFICATION_EDITOR_PRE_SAVE`/`POST_SAVE` | 9001/9002 | 编辑器保存前后 |

### 进入树与 ready 传播

- `_propagate_enter_tree`（`node.cpp:341`）：深度优先递归，先 `NOTIFICATION_ENTER_TREE` + `_enter_tree`，再处理子节点，最后该节点进入处理队列。这是「父先于子收到 enter_tree」的保证。
- `_propagate_ready`（`node.cpp:323`）：与 enter_tree 相反，**子节点先 ready，父节点后 ready**（`node.cpp:327` 先递归子节点）。这保证父节点 `_ready` 时所有子节点已就绪。
- `NOTIFICATION_READY` 时，若检测到脚本覆写了 `_process`/`_physics_process`/`_input` 等虚函数，自动调用对应 `set_process(true)`（`node.cpp:272-276`），无需用户显式开启。

### 处理回调

- `set_process(bool)`（`node.cpp:1025`）/ `set_physics_process(bool)`（`node.cpp:617`）：开启逻辑/物理处理，节点被加入对应处理列表。
- `set_process_internal`/`set_physics_process_internal`：内部处理通道，与脚本 `_process` 分离（用于引擎内部逻辑）。
- `set_process_input`/`set_process_unhandled_input`/`set_process_shortcut_input`/`set_process_unhandled_key_input`（`node.h:679-688`）：开启四档输入处理。
- `set_process_priority`/`set_physics_process_priority`（`node.h:670/676`）：处理优先级，数值越小越早。
- `can_process()`（`node.cpp:907`）：综合「在树中 + 未挂起 + 暂停策略」判断本帧是否应处理。
- `queue_free()`（`node.h:787`）：标记延迟删除，实际删除发生在 `SceneTree::_flush_delete_queue`（见下文）。

### ProcessMode 暂停策略

`ProcessMode`（`node.h:79-84`）决定暂停时节点是否仍处理：

```
INHERIT        // 继承父节点
PAUSABLE       // 暂停时不处理（默认）
WHEN_PAUSED    // 仅暂停时处理
ALWAYS         // 始终处理
DISABLED       // 从不处理
```

`_can_process(bool p_paused)`（`node.cpp:911`）沿 `process_owner` 链解析最终策略。切换时向子树传播 `NOTIFICATION_PAUSED/UNPAUSED` 与 `NOTIFICATION_DISABLED/ENABLED`（`node.cpp:698-714`）。

### 分组与节点查询

- `add_to_group`/`remove_from_group`/`is_in_group`（`node.h:573-575`）：节点可属于多个命名分组，`persistent` 标志决定是否随场景保存。
- `get_node(NodePath)`/`has_node`/`find_child`/`find_parent`（`node.h:539-549`）：按路径或模式查询节点。`NodePath` 支持子路径与属性路径。
- `get_tree()`（`node.h:558`）：获取所属 `SceneTree`（`is_inside_tree` 判断）。
- `add_child`/`remove_child`/`add_sibling`/`reparent`（`node.h:525-547`）：树结构操作，触发对应 notification 与处理队列维护。

## SceneTree 主循环

`SceneTree`（`scene/main/scene_tree.h:89 : public MainLoop`）是 `MainLoop` 的默认实现（见 [01 启动与主循环](01-启动与主循环.md)）。`_THREAD_SAFE_CLASS_` 宏声明其线程安全契约（见 [07 OS 与平台抽象](07-OS与平台抽象.md)）。

### 成员概要（`scene_tree.h:97-218`）

- `Window *root`（`scene_tree.h:133`）：根窗口，所有内容的容器。
- `ProcessGroup`（`scene_tree.h:100`）：处理分组，含 `CallQueue call_queue` + 节点列表 + 脏标志。节点按「处理线程组」归入不同 ProcessGroup，可并行处理。
- `default_process_group`（`scene_tree.h:122`）：默认单线程组。
- `HashMap<StringName, SceneTreeGroup> group_map`（`scene_tree.h:148`）：分组名 → 节点列表（`SceneTreeGroup`，`scene_tree.h:84`）。
- `List<ObjectID> delete_queue`（`scene_tree.h:188`）：`queue_free` 的待删节点。
- `current_scene`/`pending_new_scene_id`（`scene_tree.h:203-205`）：当前主场景与待切换场景。
- `scene_tree_fti`（`scene_tree.h:159`）：固定步长插值器。
- 内置信号：`tree_changed`/`node_added`/`node_removed`/`node_renamed`（`scene_tree.h:161-164`），`physics_frame`/`process_frame`（在 `physics_process`/`process` 中 emit）。

### 处理流程

`Main::iteration` 调用 `SceneTree::physics_process` 与 `process`（见 [01](01-启动与主循环.md)）：

**`physics_process`（`scene_tree.cpp:639`）**：
```
physics_process(delta)
 ├─ current_frame++
 ├─ flush_transform_notifications()
 ├─ MainLoop::physics_process()        ← 基类（基本空）
 ├─ emit "physics_frame"
 ├─ call_group("_picking_viewports", "_process_picking")  ← 视口拾取
 ├─ _process(true)                     ← 驱动所有节点的 _physics_process（见下）
 ├─ _flush_ugc()                       ← 唯一分组调用(unique group calls)
 ├─ MessageQueue::flush()
 ├─ process_timers(delta, physics=true)
 ├─ process_tweens(delta, physics=true)
 ├─ flush_transform_notifications()
 ├─ _flush_delete_queue()              ← 执行 queue_free 的节点
 └─ _call_idle_callbacks()
```

**`process`（`scene_tree.cpp:688`）**：类似，但先做 FTI 帧更新（`scene_tree.cpp:690-698`），poll 多人 API，emit `process_frame`，调用 `_process(false)` 驱动 `_process` 回调，最后处理场景切换 `_flush_scene_change`（`scene_tree.cpp:725`）。

`_process(bool p_physics)`（经 `_process_groups_thread`，`scene_tree.cpp:1238`）遍历各 ProcessGroup，按优先级对组内节点发 `NOTIFICATION_PHYSICS_PROCESS`/`NOTIFICATION_PROCESS`。若启用多线程处理组，用 `WorkerThreadPool::add_template_group_task` 并行（`scene_tree.cpp:1313`）。

### 分组调用与删除队列

- `call_group`/`call_group_flags`（`scene_tree.cpp:361`）：对分组内所有节点调用方法，变长参数（`bind_vararg_method`，见 [03](03-类型系统与反射.md)）。
- `notify_group`/`notify_group_flags`（`scene_tree.cpp:454`）：对分组发 notification。
- `_flush_ugc`（`scene_tree.cpp:320`）：刷新「唯一分组调用」去重队列（`unique_group_calls`，`scene_tree.h:195`），避免同帧重复调用。
- `_flush_delete_queue`（`scene_tree.cpp:1626`）：实际 `memdelete` 所有 `queue_free` 标记的节点。`nodes_removed_on_group_call`（`scene_tree.h:186`）保护分组调用期间被删的节点。

### 场景切换

- `change_scene_to_file`/`change_scene_to_packed`：设置 `pending_new_scene_id`，在 `process` 末由 `_flush_scene_change`（`scene_tree.cpp:216`）完成切换：释放旧 `current_scene`，实例化新场景并 `add_child` 到 root。

## ProcessGroup 与多线程处理

`SceneTree` 4.x 引入「处理线程组」（ProcessThreadGroup）机制：

- `set_process_thread_group`（`node.h:774`）+ `set_process_thread_group_order`（`node.h:673`）：把一组节点绑定到独立 ProcessGroup 并指定相对顺序。
- 每个 `ProcessGroup` 持有自己的 `CallQueue`（`scene_tree.h:101`），组内节点的 `call_deferred` 进入组队列。
- 处理时，无依赖的 ProcessGroup 可通过 `WorkerThreadPool` 并行执行（`scene_tree.cpp:1313`），组内仍按顺序。
- `node_threading_disabled`（`scene_tree.h:124`）可全局关闭该优化回退到单线程。

这让部分子树能并行处理，是 4.x 性能改进的关键。

## Viewport / Window / CanvasItem

### Viewport（`scene/main/viewport.h:96 : public Node`）

`Viewport` 是渲染与输入的根容器，不一定是窗口：

- 渲染：持 `World2D`/`World3D`（`set_world_2d`/`find_world_2d`，`viewport.h:552/554`、`set_world_3d`/`find_world_3d`，`viewport.h:880/882`），对应 `RenderingServer` 的 viewport RID。子节点 `CanvasItem`/`Node3D` 绘制到此处。
- 输入：`push_input`/`push_unhandled_input`（`viewport.h:633/635`）泵送 `InputEvent`，经四档分发：`input_group` → `shortcut_input_group` → GUI → `unhandled_input_group` → `unhandled_key_input_group`（`viewport.h:297-300`）。`set_input_as_handled`（`viewport.h:687`）阻止后续传播。
- `SubViewport`（`viewport.h:900`）：嵌入式视口，渲染到纹理。

### Window（`scene/main/window.h`）

`Window : public Viewport`，是真正的顶层窗口（与 `DisplayServer` 窗口对应）。`SceneTree::root` 是一个 `Window`。窗口可嵌套（嵌入式子窗口）。

### CanvasItem（`scene/main/canvas_item.h:47 : public Node`）

2D 可绘制节点基类（`Node2D`、`Control` 都派生自它）：

- `NOTIFICATION_DRAW=30`（`canvas_item.h:236`）：要求重绘时收到，调用 `_draw` 虚函数（`GDVIRTUAL0(_draw)`，`canvas_item.h:231`）。
- `NOTIFICATION_TRANSFORM_CHANGED=2000`（`canvas_item.h:235`）：变换变化（与 SceneTree 常量同步）。
- `queue_redraw()`（`canvas_item.h:297`）：标记需重绘，下一帧触发 `NOTIFICATION_DRAW`。
- `CanvasItem` 通过 `RenderingServer` 的 canvas item RID 绘制，受所属 `Viewport` 的 canvas 与 `CanvasLayer` 影响。

`CanvasLayer`（`scene/main/canvas_layer.h`）：独立 2D 图层，有自己的变换与层级，可叠加在主 canvas 之上。

## PackedScene 场景序列化

`PackedScene`（`scene/resources/packed_scene.h:248 : public Resource`）把节点树序列化为可实例化的资源，是「场景即数据」的核心。

### 结构

- `SceneState`（`packed_scene.h` 内部）：实际存储。记录节点列表（类型、名字、父节点索引、owner、分组、属性、实例引用）、节点实例链（场景继承）、连接、可编辑属性等。
- `pack(Node *p_scene)`（`packed_scene.h:270`）：遍历节点树生成 `SceneState`。
- `instantiate(GenEditState)`（`packed_scene.h:275`）：从 `SceneState` 重建节点树。

### 实例化流程

1. 遍历 `SceneState` 的节点列表，按 `ClassDB::instantiate` 创建各节点（见 [03 类型系统与反射](03-类型系统与反射.md)）。
2. 按父节点索引建立父子关系。
3. 应用属性（经 `Node::set`，受 `PROPERTY_USAGE_STORAGE` 标志筛选）。
4. 处理场景继承：若节点是另一 PackedScene 的实例，递归实例化后覆写属性（`GEN_EDIT_STATE_MAIN_INHERITED`，`packed_scene.h:267` 用于编辑器继承编辑）。
5. 实例化完成后发 `NOTIFICATION_SCENE_INSTANTIATED`（`node.h:467`），加入树后正常走 `enter_tree`/`ready`。

### GenEditState

`GenEditState`（`packed_scene.h:264-267`）控制实例化时的编辑器上下文：`DISABLED`（运行时）、`INSTANCE`/`MAIN`/`MAIN_INHERITED`（编辑器不同编辑状态），影响占位节点与继承处理。运行时只用 `DISABLED`。

`.tscn` 文本格式由 `SceneState` 经 `Variant` 文本序列化生成（见 [05 资源系统](05-资源系统.md)），`.scn` 为二进制格式。

## 场景层类型注册

`register_scene_types()`（`scene/register_scene_types.cpp`）在启动时注册场景层全部类型（见 [01](01-启动与主循环.md) 时序表）：`Node`、`SceneTree`、`Viewport`、`Window`、`CanvasItem`、`Timer`、`PackedScene`、各 `Resource`、2D/3D/GUI 节点等。`register_scene_singletons` 把 `SceneTree` 等注册为 `Engine` 单例。

## 与其他子系统关系

- **主循环**：`SceneTree` 实现 `MainLoop`，由 `Main::iteration` 驱动，见 [01 启动与主循环](01-启动与主循环.md)。
- **对象系统**：`Node` 派生自 `Object`，靠 `notification`/`ObjectID`/`MessageQueue` 串联，`queue_free` 经 `ObjectDB` 安全删除，见 [02 对象系统](02-对象系统.md)。
- **类型系统**：`Node`/`PackedScene` 经 `GDCLASS` 注册，`PackedScene` 序列化依赖 `PropertyInfo` 与 Variant，见 [03 类型系统与反射](03-类型系统与反射.md)。
- **资源系统**：`PackedScene` 是 `Resource`，由 `ResourceLoader` 加载，见 [05 资源系统](05-资源系统.md)。
- **服务器**：`Viewport`/`CanvasItem`/`Node3D` 是渲染服务器前端，`CollisionObject` 是物理服务器前端，见 [06 服务器架构](06-服务器架构.md)。
- **脚本**：`Node` 的 `_process`/`_ready` 等经 `GDVIRTUAL` 被脚本覆写，见 [08 脚本与扩展](08-脚本与扩展.md)。
