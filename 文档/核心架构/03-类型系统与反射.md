# 03 类型系统与反射

## 职责定位

类型系统与反射解决一个核心问题：让 C++ 编写的引擎类能在运行时被**统一地、动态地**认知和操纵--包括按名字实例化、枚举属性与方法、动态调用、序列化、在编辑器里展示属性面板、绑定到脚本语言。它由两大支柱构成：

1. **`ClassDB`**：全局反射注册表，记录所有引擎类的元信息（基类、方法、属性、信号、常量）。
2. **`Variant`**：可持有任意内置类型的动态类型联合体，是脚本↔C++、序列化、属性系统的统一数据载体。

两者加上 `Object`（见 [02 对象系统](02-对象系统.md)）共同构成 Godot「反射驱动工具链」的基础。代码位于 `core/object/` 与 `core/variant/`。

## ClassDB 反射注册表

`ClassDB`（`core/object/class_db.h:97`）是引擎唯一的全局反射表，全部为静态成员。

### 数据结构

每个注册类对应一个 `ClassInfo`（`class_db.h:120`）：

```cpp
struct ClassInfo {
    APIType api = API_NONE;            // API_CORE/EDITOR/EXTENSION...
    ClassInfo *inherits_ptr;           // 父类链
    GDType *gdtype;                    // 类型描述
    ObjectGDExtension *gdextension;    // GDExtension 类信息

    HashMap<StringName, MethodBind *> method_map;            // 方法
    HashMap<StringName, LocalVector<MethodBind *>> method_map_compatibility; // 兼容方法
    List<PropertyInfo> property_list;                        // 属性（顺序）
    HashMap<StringName, PropertyInfo> property_map;          // 属性（查找）
    AHashMap<StringName, PropertySetGet> property_setget;    // setter/getter 绑定

    bool disabled, exposed, is_virtual, is_runtime;
    Object *(*creation_func)(bool);    // 实例化工厂
};
```

全局容器（`class_db.h:194-196`）：`classes`（类名 -> ClassInfo）、`resource_base_extensions`（资源扩展名映射）、`compat_classes`（兼容重命名映射）。访问由递归读写锁 `Locker`（`class_db.h:172`）保护，支持 GDExtension 运行时重载类的嵌套加锁。

### API 分层

`APIType`（`class_db.h:102`）划分反射来源层级：`API_CORE`、`API_EDITOR`、`API_EXTENSION`（GDExtension）、`API_EDITOR_EXTENSION`。`current_api`（`class_db.h:208`）在注册时设置，使注册的类自动归入对应层级；`get_api_hash(APIType)`（`class_db.h:353`）为各层生成稳定哈希，GDExtension 用它校验 ABI 兼容性。

### 注册类：register_class

`ClassDB::register_class<T>`（`class_db.h:245`）是注册入口：

```cpp
template <typename T>
static void register_class(bool p_virtual = false) {
    T::initialize_class();                       // 触发 _bind_methods
    ClassInfo *t = classes.getptr(T::get_class_static());
    t->creation_func = &creator<T>;              // 工厂函数
    t->is_virtual = p_virtual;
    t->api = current_api;
}
```

`creator<T>`（`class_db.h:160`）用 `DefaultAllocator` 构造并按需发送 `NOTIFICATION_POSTINITIALIZE`。注册变体由宏封装（`class_db.h:568-589`）：

| 宏 | 含义 |
|----|------|
| `GDREGISTER_CLASS(T)` | 普通可实例化类 |
| `GDREGISTER_VIRTUAL_CLASS(T)` | 虚类（`register_class(true)`） |
| `GDREGISTER_ABSTRACT_CLASS(T)` | 抽象类，无 `creation_func` |
| `GDREGISTER_INTERNAL_CLASS(T)` | 内部类（不暴露给脚本） |
| `GDREGISTER_RUNTIME_CLASS(T)` | 运行时可重载类（GDExtension 热重载） |

所有宏都先经 `GD_IS_CLASS_ENABLED(T)` 编译期判断，支持用 `module_*=no` 关闭可选类。

## GDCLASS 宏：声明的魔法

`GDCLASS(m_class, m_inherits)`（`core/object/object.h:248`）是每个引擎类必须使用的宏，它展开为一系列静态/虚函数，把 C++ 类接入反射体系。关键展开内容：

1. **`get_gdtype_static_mutable()`**（`object.h:254`）：惰性创建 `GDType`（含类名 `StringName(#m_class)` 与父类 `GDType`），双检锁保证线程安全。`GDType` 是 4.x 后期引入的类型描述对象，承载 `AncestralClass` 等元信息。

2. **`initialize_class()`**（`object.h:292`）：注册流程核心。递归先初始化父类（`m_inherits::initialize_class()`），调用 `_add_class_to_classdb` 把自身加入 ClassDB，然后**仅当本类覆写了 `_bind_methods`** 时调用它（`object.h:306` 的指针比较避免重复绑定父类方法）。

3. **`_get_property_listv`**（`object.h:322`）：属性列表虚函数链。按继承顺序（或逆序 `p_reversed`）拼装父类属性 + 自身 `_get_property_list` + ClassDB 中登记的属性，并在每层插入一个 `PROPERTY_USAGE_CATEGORY` 类别标题（`object.h:326`）。这是编辑器属性面板分层显示的来源。

4. **`self_type`/`super_type`**（经 `GDSOFTCLASS`，`object.h:161`）：供 `cast_to`、`derives_from` 做静态与位域类型判断（见 [02 对象系统](02-对象系统.md) 的 `AncestralClass`）。

### GDVIRTUAL 虚方法绑定

`GDVIRTUAL` 宏族（`object.h:141-151`）让 C++ 虚方法能被脚本/GDExtension 覆写：

- 声明：`GDVIRTUAL1R(bool, _physics_process, double)` 在类中展开为 `_gdvirtual__physics_process_call` 等方法。
- 调用：`GDVIRTUAL_CALL(_physics_process, delta, res)` 检查脚本/扩展是否覆写并调用。
- 绑定：`GDVIRTUAL_BIND(_physics_process)`（仅 DEBUG）把虚方法登记到 ClassDB 的 `virtual_methods`（`class_db.h:137`），供编辑器与文档识别。
- `GDVIRTUAL_IS_OVERRIDDEN`（`object.h:150`）查询某虚方法是否被脚本覆写，用于跳过无谓调用。

## 方法绑定：MethodBind

`MethodBind`（`core/object/method_bind.h:38`）是方法绑定的抽象基类，把 C++ 成员函数包装成可被反射调用的对象：

```cpp
class MethodBind {
    StringName name, instance_class;
    Vector<Variant> default_arguments;
    int argument_count;
    bool _static, _const, _returns;
    virtual Variant call(Object*, const Variant**, int, CallError&) const = 0;
    virtual void validated_call(Object*, const Variant**, Variant*) const = 0;  // 无错误检查，快速路径
    virtual void ptrcall(Object*, const void**, void*) const = 0;              // 原生指针调用，零 Variant 转换
};
```

- 三种调用路径：`call`（带类型检查与错误回报）、`validated_call`（假设参数已校验，无运行时检查）、`ptrcall`（直接传原生指针，用于紧密循环如脚本绑定，零开销）。
- `create_method_bind` 模板工厂根据方法签名生成具体特化类（普通/const/static/vararg 等），自动推导参数类型。
- `MethodBindVarArgBase`（`method_bind.h:142`）及 `MethodBindVarArgT/TR`（`method_bind.h:220/254`）支持变长参数方法（如 `Node::call`）。

### 绑定 API

在类的 `_bind_methods()` 中使用（参数推导自方法签名）：

- `ClassDB::bind_method(D_METHOD("name"), &Class::method, defaults...)`（`class_db.h:374`）：绑定实例方法。
- `bind_static_method`（`class_db.h:388`）：静态方法。
- `bind_vararg_method`（`class_db.h:432`）：变长参数方法。
- `bind_compatibility_method`（`class_db.h:403`）：注册旧签名兼容方法，供旧版 GDExtension 调用。
- `D_METHOD("name", "arg1", ...)` 宏生成 `MethodDefinition`，DEBUG 下记录参数名供文档/补全。

## 属性绑定

属性通过 setter/getter 绑定，元信息由 `PropertyInfo`（`property_info.h:124`）描述：

```cpp
struct PropertyInfo {
    Variant::Type type;       // Variant::INT, OBJECT, ...
    String name;              // 属性名
    StringName class_name;    // 对象类型的类名
    PropertyHint hint;        // 编辑提示
    String hint_string;       // 提示文本
    uint32_t usage;           // 用途标志位
};
```

- `PropertyHint`（`property_info.h:39`）：`PROPERTY_HINT_RANGE`（数值范围）、`ENUM`（枚举）、`FILE`（文件选择）、`RESOURCE_TYPE`（资源类型过滤）、`LAYERS_2D_PHYSICS`（图层位掩码）等数十种，决定编辑器中属性的呈现控件。
- `PropertyUsageFlags`（`property_info.h:88`）：`PROPERTY_USAGE_STORAGE`（序列化）、`EDITOR`（编辑器可见）、`INTERNAL`、`GROUP`/`CATEGORY`/`SUBGROUP`（分组）、`READ_ONLY`、`NO_INSTANCE_STATE` 等。`PROPERTY_USAGE_DEFAULT = STORAGE | EDITOR`。
- `add_property(class, PropertyInfo, setter, getter)`（`class_db.h:469`）：登记属性及其 setter/getter 方法名（存入 `property_setget`，`class_db.h:147`）。
- `add_property_group`/`add_property_subgroup`（`class_db.h:465-466`）：插入分组标题。
- 动态属性：类可覆写 `_get_property_list` 运行时增补属性，编辑器与序列化都会尊重。

`MethodInfo`（`method_info.h:48`）是方法的等价物：`{ name, return_val, flags, arguments, default_arguments }`，含 `MethodFlags`（`method_info.h:36`：`CONST`/`VIRTUAL`/`VARARG`/`STATIC`）。`MethodInfo::get_compatibility_hash()`（`method_info.h:73`）为 GDExtension ABI 校验生成方法哈希。

## Variant 动态类型

`Variant`（`core/variant/variant.h`，`enum Type` 在 `variant.h:97`）是 Godot 的动态类型，可持有全部内置类型。类型枚举（`variant.h:97-147`）：

- **原子**：`NIL`、`BOOL`、`INT`、`STRING`
- **数学**：`VECTOR2/2I`、`RECT2/2I`、`VECTOR3/3I`、`TRANSFORM2D`、`VECTOR4/4I`、`PLANE`、`QUATERNION`、`AABB`、`BASIS`、`TRANSFORM3D`、`PROJECTION`
- **杂项**：`COLOR`、`STRING_NAME`、`NODE_PATH`、`RID`、`OBJECT`、`CALLABLE`、`SIGNAL`、`DICTIONARY`、`ARRAY`
- **类型化数组**：`PACKED_BYTE_ARRAY`…`PACKED_VECTOR4_ARRAY`（紧凑连续存储）
- `VARIANT_MAX`

### 实现要点

- `Variant` 是带类型标签的联合体（`variant.h` 内部 `PackedArray`/对象指针等共用存储），16 字节对齐优化。`Callable` 被约束 `<=16` 字节（`register_core_types.cpp:138` 的 static_assert）。
- **运算符**：`variant_op.cpp` 实现全部类型间的运算符（算术、比较、逻辑、类型构造），通过 `Variant::evaluate(op, a, b, r_ret, r_valid)` 统一分发。
- **动态调用**：`variant_call.cpp` 实现 `Variant` 上对内置类型方法的动态调用（如 `Vector2.round()`），方法表按类型注册（`Variant::register_types()`，`register_core_types.cpp:156`）。
- **与 Object 的关系**：`Variant::OBJECT` 持有 `Object*`（经 `ObjectID` 间接解析），`RefCounted` 对象以 `Ref` 形式持有以维持引用计数；`is_ref_counted()` 判断（见 [02 对象系统](02-对象系统.md)）。
- **序列化**：`variant_parser.cpp` 实现文本序列化（`.tres`/`.tscn`），`marshalls.cpp` 实现二进制序列化，二者以 `Variant` 为中枢。

`Variant` 让脚本语言无需为每个内置类型单独绑定：脚本里 `vec2.x`、`dict["key"]`、`obj.method()` 最终都落到 `Variant` 的统一操作上。`Variant` 也是属性值、信号参数、网络 RPC 的标准传输格式。

## 注册总时序

类型注册按引擎层级在启动时依次进行（见 [01 启动与主循环](01-启动与主循环.md)），入口在 `main/main.cpp`：

| 顺序 | 调用 | 位置 | 注册内容 |
|------|------|------|----------|
| 1 | `register_core_types()` | `main.cpp:992` (setup) | core 层类：Object/RefCounted/Resource/Variant 类型/InputEvent 等，见 `register_core_types.cpp:134` |
| 2 | `register_core_driver_types()` | `main.cpp:993` | 驱动层（图像/音频驱动） |
| 3 | `register_server_types()` | `main.cpp:3134` (setup2) | 服务器层接口类 |
| 4 | `initialize_modules(SERVERS)` + GDExtension | `main.cpp:3138` | 模块/GDExtension 服务器级类型 |

| 6 | `initialize_modules(SCENE)` + GDExtension | `main.cpp:3694` | 模块/GDExtension 场景级类型 |
| 7 | `register_editor_types()` (tools) | `main.cpp:3713` | 编辑器层类型 |

每层注册前，`ClassDB::set_current_api(...)`（如 `main.cpp:3712` 切到 `API_EDITOR`）设置当前 API 归属。`unregister_*_types` 在 cleanup 时按逆序执行（见 [01](01-启动与主循环.md)）。

`register_core_types()`（`register_core_types.cpp:134`）本身还做基础设施初始化：`ObjectDB::setup()`、`StringName::setup()`、`register_global_constants()`、`ResourceLoader::initialize()`、`Variant::register_types()`，并注册第一批核心类（`Object`/`RefCounted`/`Resource`，`register_core_types.cpp:147-150`）。

## 反射如何驱动工具链

同一份 ClassDB 元信息被多方消费，这是 Godot「编辑器即引擎」能力的关键：

- **脚本绑定**：GDScript/GDExtension 通过 ClassDB 获取类的方法/属性/信号签名，生成绑定代码或运行时查找表。`Object::callp`/`set`/`get` 经 ClassDB 派发到 `MethodBind`/`PropertySetGet`。
- **编辑器属性面板**：`Object::get_property_list`（由 `GDCLASS` 展开的 `_get_property_listv`，`object.h:322`）拼装出含分组的属性列表，`PropertyHint`/`usage` 决定每个属性的编辑控件。改值时 `set` -> ClassDB setter。
- **自动文档**：`editor/doc/` 遍历 ClassDB 生成类参考文档（`--doctool`）。
- **序列化**：场景/资源序列化按 `PROPERTY_USAGE_STORAGE` 标志筛选属性，值以 `Variant` 文本/二进制形式写入。
- **网络 RPC**：`Callable::rpcp` 通过方法名与 Variant 参数跨网络调用。
- **GDExtension 兼容**：`get_api_hash` 与 `MethodInfo::get_compatibility_hash` 让扩展库在加载时校验 ABI。

## 与其他子系统关系

- **对象系统**：`ClassDB` 依赖 `Object` 的 `GDCLASS`/`AncestralClass`/`ObjectDB`，`Object::callp` 把调用转回 ClassDB，见 [02 对象系统](02-对象系统.md)。
- **节点/资源**：`Node`/`Resource` 经 `GDCLASS` 注册，`PackedScene` 序列化依赖 `PropertyInfo` 与 Variant，见 [04 节点与场景树](04-节点与场景树.md)、[05 资源系统](05-资源系统.md)。
- **服务器**：Server 接口类用 `GDREGISTER_VIRTUAL_CLASS` 注册，前端节点通过 ClassDB 调用服务器方法，见 [06 服务器架构](06-服务器架构.md)。
- **脚本/扩展**：GDExtension 在加载时用 `get_api_hash` 校验，运行时通过 `ObjectGDExtension`（`object.h` 顶部）把扩展类接入 ClassDB，见 [08 脚本与扩展](08-脚本与扩展.md)。
- **编辑器**：属性面板、文档生成、自动补全都以 ClassDB 元信息为数据源，见 [09 编辑器架构](09-编辑器架构.md)。
