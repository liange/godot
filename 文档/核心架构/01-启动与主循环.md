# 01 启动与主循环

## 职责定位

启动与主循环是引擎的「心脏」：它负责从平台入口（`main()`）一路把引擎初始化到可运行状态，然后驱动一个持续不断的帧循环，按固定步长推进物理、按可变步长推进逻辑与渲染，最后干净地释放一切。代码主要集中在 `main/` 目录。

理解本章是理解其他所有子系统的前提——所有类型注册、服务器创建、主循环装配都发生在启动阶段。

## 设计意图：三阶段初始化

`main.cpp:935` 的注释明确说明初始化分三步，且由各平台 `main()` 依次调用：

1. **`setup(execpath, argc, argv, p_second_phase)`**（`main.cpp:960`）：初始化底层单例与核心类型，解析命令行。`p_second_phase=true` 时自动链入 `setup2()`；Android/iOS 设为 `false`，由平台在适当时机自行触发第二阶段。
2. **`setup2(p_show_boot_logo)`**（`main.cpp:2945`）：注册高层服务器与单例，显示启动画面，注册更高层类型（scene/editor）。
3. **`start()`**（`main.cpp:3911`）：最后一步，解析剩余命令行、创建主循环、装载游戏场景或编辑器节点。

这样分层是因为部分平台（移动端）的窗口/上下文在 `setup` 之后才可用，需要拆分时机。

## 平台入口

以 Windows 为例（`platform/windows/godot_windows.cpp:68` 的 `widechar_main`）：

```
main() -> _main() -> widechar_main()
  OS_Windows os(nullptr)
  Main::setup(argv)              // 第一阶段（自动进入第二阶段）
  if (Main::start() == OK):
      os.run()                   // 进入帧循环
  Main::cleanup()
```

`OS_Windows::run()`（`platform/windows/os_windows.cpp:2348`）就是真正的帧循环宿主：

```cpp
void OS_Windows::run() {
    main_loop->initialize();          // 2348: 主循环初始化
    while (true) {
        DisplayServer::get_singleton()->process_events();  // 泵送窗口事件
        if (Main::iteration()) break; // 2359: 返回 true 表示请求退出
    }
    main_loop->finalize();            // 2364: 主循环终结
}
```

> 注意：主循环的 `initialize()`/`finalize()` 在平台 `OS::run()` 中调用，而每帧推进则委托给引擎无关的 `Main::iteration()`。这是「平台负责事件泵与生命周期、引擎负责帧逻辑」的分工。

## setup()：核心层初始化

`Main::setup`（`main.cpp:960`）的关键动作：

1. `Thread::make_main_thread()` + `set_current_thread_safe_for_nodes(true)`：标记当前线程为主线程（节点系统依赖此标记，见 [02 对象系统](02-对象系统.md)）。
2. `OS::get_singleton()->initialize()`：平台 OS 底层初始化。
3. `engine = memnew(Engine)`：创建 `Engine` 单例。
4. `register_core_types()` + `register_core_driver_types()`：注册核心类型到 `ClassDB`（见 [03 类型系统与反射](03-类型系统与反射.md)）。
5. `globals = memnew(ProjectSettings)`、`register_core_settings()`：项目设置与核心设置。
6. 创建 `InputMap`、`TranslationServer`、`Performance` 单例。
7. 解析命令行参数（`main.cpp:1015` 起）。

> 此阶段只注册 **core** 层类型，尚未创建任何渲染/物理服务器。

## setup2()：服务器与高层类型

`Main::setup2`（`main.cpp:2945`）负责把引擎从「裸核心」装配到「可渲染」，关键时序：

1. 文本/物理/导航服务器管理器初始化（`main.cpp:3113-3132`）：`TextServerManager`、`PhysicsServer(2D/3D)Manager`、`NavigationServer(2D/3D)Manager` 的 `initialize_server_manager()`。
2. `register_server_types()`（`main.cpp:3134`）：注册服务器层类型。
3. `initialize_modules(MODULE_INITIALIZATION_LEVEL_SERVERS)` + GDExtension 服务器级初始化（`main.cpp:3138-3139`）。
4. 创建 `Input`（`main.cpp:3149`）、初始化 `DisplayServer`（`main.cpp:3157`）——显示服务器在此可用。
5. 实际创建渲染/物理/导航服务器实例（`initialize_server()`，`main.cpp:3680` 附近）。
6. `register_scene_types()` + `register_driver_types()`（`main.cpp:3686-3687`）：注册场景层与驱动类型。
7. `register_scene_singletons()`。
8. `initialize_modules(MODULE_INITIALIZATION_LEVEL_SCENE)` + GDExtension 场景级初始化（`main.cpp:3694-3695`）。
9. （tools 构建）`register_editor_types()` + `initialize_modules(MODULE_INITIALIZATION_LEVEL_EDITOR)` + GDExtension 编辑器级初始化（`main.cpp:3713` 起）。

这体现了**注册的分层顺序**：core -> servers -> modules(server 级) -> scene -> modules(scene 级) -> editor -> modules(editor 级)。GDExtension 与模块都在每层级同步初始化。详见 [10 模块与构建](10-模块与构建.md)。

## start()：创建主循环

`Main::start`（`main.cpp:3911`）解析剩余命令行并创建主循环：

- `main_timer_sync.init(...)`（`main.cpp:3943`）：初始化时间步进器。
- 创建 `MainLoop`（`main.cpp:4260` 起）：
  - 编辑器模式：`main_loop = memnew(SceneTree)`（`main.cpp:4262`）。
  - 脚本主循环：若指定 `--script`，加载脚本并 `ClassDB::instantiate` 出 `MainLoop` 派生实例（`main.cpp:4268-4290`）。
  - 否则用 `application/run/main_loop_type` 项目设置（默认 `SceneTree`）。
- `OS::get_singleton()->set_main_loop(main_loop)`（`main.cpp:4332`）：把主循环交给 OS 持有。
- `sml = Object::cast_to<SceneTree>(main_loop)`（`main.cpp:4334`）。
- 装载内容：
  - 编辑器：`editor_node = memnew(EditorNode)` 并 `add_child` 到根（`main.cpp:4506-4507`）。
  - 项目管理器：`memnew(ProjectManager)` 挂到根（`main.cpp:4711-4715`）。
  - 游戏项目：装载主场景（`game_path`，`main.cpp:4240` 附近解析）。
- `GDExtensionManager::get_singleton()->startup()`（`main.cpp:4754`）。

## OS::run() 与主循环抽象

`MainLoop`（`core/os/main_loop.h:36`）是主循环抽象基类，派生自 `Object`：

```cpp
class MainLoop : public Object {
    GDVIRTUAL0(_initialize)
    GDVIRTUAL1R(bool, _physics_process, double)
    GDVIRTUAL1R(bool, _process, double)
    GDVIRTUAL0(_finalize)
    virtual void initialize();
    virtual bool physics_process(double p_time);
    virtual bool process(double p_time);
    virtual void finalize();
};
```

- `initialize()`/`finalize()` 在 `OS::run()` 首尾各调用一次。
- `process(delta)` / `physics_process(delta)` 每帧由 `Main::iteration()` 调用，返回 `true` 表示请求退出。
- 还定义了一批跨子系统通知常量（`NOTIFICATION_OS_MEMORY_WARNING=2009`、`NOTIFICATION_APPLICATION_PAUSED=2015` 等，`main_loop.h:48-62`），通过 `notification(int)` 广播。
- `SceneTree`（`scene/main/scene_tree.h:89 : public MainLoop`）是默认实现，把 `process`/`physics_process` 转发给整棵 `Node` 树。详见 [04 节点与场景树](04-节点与场景树.md)。

## 单帧 iteration() 流程

`Main::iteration`（`main.cpp:4817`）是每帧的核心，固定/可变步长混合调度：

```
iteration()
 ├─ 读取 CPU ticks，main_timer_sync.advance() 算出 MainFrameTime
 │     {process_step, physics_steps, interpolation_fraction}
 ├─ XRServer::_process()
 ├─ for (physics_steps 次):              ← 固定步长物理循环
 │     ├─ Input::flush_buffered_events() (agile 输入)
 │     ├─ main_loop->iteration_prepare()  ← FTI 插值准备
 │     ├─ PhysicsServer(3D/2D)::sync() + flush_queries()
 │     ├─ main_loop->physics_process(step) ← 驱动 Node._physics_process
 │     ├─ NavigationServer(2D/3D)::physics_process()
 │     ├─ message_queue->flush()           ← 处理延迟调用
 │     ├─ PhysicsServer(3D/2D)::end_sync() + step()
 │     ├─ message_queue->flush()
 │     └─ main_loop->iteration_end()
 ├─ Input::flush_buffered_events()
 ├─ main_loop->process(step)             ← 可变步长，驱动 Node._process
 ├─ message_queue->flush()
 ├─ NavigationServer(2D/3D)::process()
 ├─ RenderingServer::sync()              ← 同步上一帧绘制
 ├─ RenderingServer::draw()              ← 提交本帧渲染命令
 ├─ GDExtensionManager::frame()
 ├─ 各 ScriptLanguage::frame()           ← 脚本语言帧清理
 ├─ AudioServer::update()
 ├─ EngineDebugger::iteration(...)
 ├─ FPS/性能统计更新
 └─ OS::add_frame_delay()                ← 低功耗模式或帧延迟
```

关键点（行号对应 `main.cpp`）：

- 时间步进：`main_timer_sync.advance(physics_step, physics_ticks_per_second)`（`main.cpp:4834`），返回 `MainFrameTime`。
- `time_scale`：全局时间缩放（`main.cpp:4832`），作用于物理与逻辑步长。
- 物理步数封顶：`max_physics_steps_per_frame`，超出则把超量时间累加到 `process_step`，防止「死亡螺旋」（`main.cpp:4851-4855`）。
- 物理与逻辑分离：物理循环 `for (iters < physics_steps)` 在 `main.cpp:4866`，逻辑 `process()` 在 `main.cpp:4958`。
- `MessageQueue::flush()` 在物理循环内与逻辑后各刷一次，保证延迟调用及时执行（见 [02 对象系统](02-对象系统.md)）。
- 渲染：`RenderingServer::sync()` 先同步上帧，再 `draw()` 提交本帧（`main.cpp:4973-4993`）。低功耗模式下仅在有变化时绘制。
- 返回值 `exit`：任意一步主循环返回 `true` 或 `quit_after` 到期即请求退出。

## MainTimerSync 时间步进

`main/main_timer_sync.h:43` 的 `MainTimerSync` 决定每帧执行多少物理步、逻辑步多大：

- `MainFrameTime`（`main_timer_sync.h:35`）：`{process_step, physics_steps, interpolation_fraction}`。
- `advance()`（`main_timer_sync.h:144`）：基于墙钟时间累积 `time_accum`（`main_timer_sync.h:95`），每攒满一个 `physics_step` 就产出一个物理步。
- `DeltaSmoother`（`main_timer_sync.h:44`）：估算显示器刷新率（`_vsync_delta` 默认 16666us≈60Hz）、平滑 delta，在 144Hz 显示器上配合 60Hz 物理时表现良好（`CONTROL_STEPS=12`，`main_timer_sync.h:104`）。
- `fixed_fps`：`--fixed-fps` 模式下用固定步长，常用于录制视频/离线渲染。
- 插值分数 `interpolation_fraction`：用于物理插值，让渲染处在两个物理 tick 之间时变换平滑。

## cleanup()

`Main::cleanup`（`main.cpp:5112`）按**逆序**释放，顺序很重要（`unregister_*` 与 `register_*` 一一对应）：

```
unregister_editor_types() -> unregister_scene_types()
 -> unregister_server_types() -> unregister_core_types()
```
（`main.cpp:5185/5196/5219/5274`），对应启动时的 `register_*` 调用。模块与 GDExtension 也按 `..._LEVEL_EDITOR/SCENE/SERVERS/CORE` 逆序 `deinitialize`。

## 测试入口

`Main::test_entrypoint`（`main.cpp:907`）：在正常启动前先扫描 `--test`。若命中且编译启用 `TESTS_ENABLED`，则调用 `test_setup()` -> `test_main(argc, argv)` -> `test_cleanup()` 直接运行 doctest 单元测试后退出，不进入游戏主循环（`main.cpp:919-922`）。这由 `main.h:89` 的 `TEST_MAIN_OVERRIDE` 宏在各平台 `main()` 顶部展开。

```
平台 main()
  │
  ├─ TEST_MAIN_OVERRIDE  →(命中 --test)→ test_entrypoint → test_main → 退出
  │
  ├─ Main::setup()          第一阶段：core 类型、ProjectSettings、单例、解析命令行
  │     └─(p_second_phase)→ Main::setup2()

  │             ├─ register_server_types() + modules(SERVERS级)
  │             ├─ 创建 Input / DisplayServer / 渲染·物理·导航服务器
  │             ├─ register_scene_types() + modules(SCENE级)
  │             └─ (tools) register_editor_types() + modules(EDITOR级)
  │
  ├─ Main::start()          第三阶段：解析剩余命令行
  │     ├─ 创建 MainLoop(默认 SceneTree) → OS::set_main_loop()
  │     ├─ 装载主场景 / memnew(EditorNode) / memnew(ProjectManager)
  │     └─ GDExtensionManager::startup()
  │
  ├─ OS::run()              帧循环宿主
  │     ├─ main_loop->initialize()
  │     ├─ while: process_events() ; Main::iteration()
  │     └─ main_loop->finalize()
  │
  └─ Main::cleanup()        逆序 unregister_* + 释放单例
```

## 与其他子系统关系

- **对象系统**：`set_current_thread_safe_for_nodes(true)` 与 `MessageQueue::flush()` 串起节点调用，见 [02 对象系统](02-对象系统.md)。
- **类型系统**：`register_*_types` 是 ClassDB 的总注册入口，见 [03 类型系统与反射](03-类型系统与反射.md)。
- **节点/场景树**：`SceneTree` 把 `iteration` 的物理/逻辑调用广播到整棵 Node 树，见 [04 节点与场景树](04-节点与场景树.md)。
- **服务器**：物理 `step/sync`、导航 `physics_process`、渲染 `sync/draw`、音频 `update` 都在帧循环内被调度，见 [06 服务器架构](06-服务器架构.md)。
- **OS/平台**：平台提供 `OS::run()` 事件泵与时间源，见 [07 OS 与平台抽象](07-OS与平台抽象.md)。
- **脚本**：每帧末 `ScriptLanguage::frame()` 做脚本侧帧清理，见 [08 脚本与扩展](08-脚本与扩展.md)。
